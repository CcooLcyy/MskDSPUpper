# 上位机静态更新上传进度方案

> **历史方案（已失效）**：本文描述的进度显示实现在 `scripts/workflow/Sync-StaticUpdater.ps1`（基于 SSH/scp 的旧静态服务器上传）。
> 该脚本已随 Cloudflare R2 迁移移除，当前上传由 `scripts/workflow/Publish-R2StaticUpdater.ps1` 承担（顺序上传，不带进度显示）。

## 目标

让上位机 CI、Beta、Nightly 和 Stable 发布到静态更新服务器时，像下位机 CI 一样输出安装包上传进度，便于判断大文件上传是否仍在进行以及预计完成时间。

## 范围

- 仅调整 `Sync-StaticUpdater.ps1` 中“更新资产”上传阶段的执行方式。
- 更新资产仍先上传，`latest.json` 仍最后上传，避免客户端读取到资产不完整的清单。
- 上传失败、静态清单校验和首个资产 URL 校验规则保持不变。
- GitHub Actions artifact 上传不作修改；它与静态服务器上传是两个独立阶段。

## 实现规则

1. 资产 `scp` 在后台进程中运行，主脚本等待其退出并保留退出码。
2. 主脚本每 10 秒通过 SSH 执行远端 `stat -c %s`，读取正在上传的主资产文件大小。
3. 日志显示已上传大小、总大小、百分比、平均速度和预计剩余时间；远端文件暂不可读时显示等待状态。
4. `scp` 结束后停止进度轮询，进程非零退出时立即失败。
5. 进度监控只观察远端文件，不修改上传内容，不改变协议或更新清单格式。

## 验收标准

- PowerShell 脚本包含异步 `scp`、每 10 秒轮询、远端文件大小读取和进度计算。
- 资产上传完成后仍单独最后上传 `latest.json`。
- 进度监控退出不会掩盖 `scp` 的真实退出码。
- 上位机工作流配置无需修改，所有调用该脚本的发布通道自动获得进度日志。
