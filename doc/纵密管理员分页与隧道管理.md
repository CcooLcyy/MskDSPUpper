# 纵密管理员分页与隧道管理

## 已确认范围

- 系统管理员认证成功后显示业务区；保持现有账号、证书、会话及串行执行机制。
- 会话信息为紧凑顶栏，业务分成“初始化与证书”和“隧道管理”，一次显示当前页。
- 初始化与证书页保留当前一键导出 SM2 CSR 及证书导入、导出、删除。导入选项收进弹窗。
- 隧道页提供列表/图示切换、手动刷新、选中单条重置及最后成功刷新时间。
- 仅接入当前可用的桌面直连认证会话；本次不扩展远程登录、不修改 DSP 下位机。

## 数据与协议边界

通过现有 `run_vertical_security_admin` 调用。`list_tunnels` 没有额外参数；`reset_tunnel` 仅携带 `tunnel_id`。后端在派发和执行前均验证已认证 role 1 会话，不接受任意文件名或命令号。

查询复用文件下载 4/5/6，固定读取运行状态文件 `tunnel`，不读取或改写配置 `tunnel.txt`。原软件参考为本地解析工程 `analysis/full-restoration/source/netkeeperui/TunFrame.java`、`TunnelState.java` 和 `TunnelModel.java`。

运行状态前九字段为 ID、状态、热备、本端地址、对端地址、加密次数、解密次数、加密错误次数、解密错误次数；其后五字段原软件跳过，再后为可选错误信息及算法。计数作为十进制字符串传至前端，防止 JavaScript 大整数精度丢失。未知状态保留原始数值；缺失可选信息显示未提供，不推断算法。原软件算法/错误信息列存在对调迹象，分别按解析成员绑定，待实际装置样本复核。

文件以 UTF-8 优先、严格 GBK 回退解析；无效编码与坏行作为错误返回，不做有损替换或部分成功。ID 按原程序实际校验范围限制为 `1..=102400`，单次最多 10240 条，重复 ID 拒绝。中间空字段保留，避免可选错误信息缺失时算法字段移位。

重置按实际调用 `ClientSendStr(18, id, null)` 发送两个大端整数，无正文；不采用与调用冲突的 `RESET_TUNNEL=17` 常量。正应答表示命令已受理，不表示隧道已经连接。弹窗确认后仅发送一次，不自动重试；随后以手动刷新观察状态。应答不完整、错命令或超时按现有机制关闭不确定连接。

## 页面与异常行为

- 页面进入和分页切换不自动发送装置请求，不自动生成密钥或重置隧道。
- 同会话各业务共用忙状态；请求期间不可发起重复操作或退出。
- 隧道查询成功为空时显示“暂无隧道”；读取或解析失败显示错误。旧数据如保留必须标记为历史结果，时间保持最后成功查询时间。
- 刷新后清理失效选择；换会话清空页面数据、选择及提示，迟到结果不能写入新会话。
- 图示由列表数据派生，不调用另一套数据源。
- 重置必须选择单条并确认；提示包含 ID 与影响，成功文案明确“命令已受理，请刷新核对”。

## 验收与验证

1. 管理员登录后能切换两页，初始化与证书操作保持原有行为，其他角色不获得管理员业务入口。
2. 模拟协议测试覆盖下载、空列表、坏行、可选字段、未知状态、大计数、重置拒绝/应答错误、会话权限及取消。
3. 前端事件测试覆盖分页、列表与图示同源、刷新错误、重置确认、忙时重复请求、换会话及卸载后的迟到结果。
4. 执行相关前端测试、类型检查、构建、lint 和 Rust 测试，报告实际范围。

以上本地验证不代替装置联调。本次不连接设备执行重置；真实状态含义、算法字段及命令效果仍需设备验证。
