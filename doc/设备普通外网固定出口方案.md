# 设备普通外网固定出口

## 已确认的行为

用户确认设备普通 IPv4 外网固定使用 `102 口（eth0.102）`、网关 `192.168.2.1`，DNS 留空，沿用系统已有解析配置。移除平台接入抽屉中的出口模式、网口、网关及 DNS 编辑控件，保留只读说明和实际应用状态。复用原有“保存并应用”，不新增按钮或开关。

此配置影响整个设备普通外网流量，与平台接入开关独立。每次通过当前上位机保存时写入固定参数；即使回读的是以前的自定义出口或未管理状态，也不能继续保存该旧值。

## 范围与兼容

- 只修改上位机界面及其请求构造，使用已有普通网络协议及运行适配器；已支持普通出口配置的下位机无需因本次界面简化再次升级。
- 下位机通用接口保留原语义，供旧客户端及旧持久配置兼容使用。本次不会自动迁移设备配置；用户保存后才应用固定出口。
- 旧下位机缺少网络支持声明时，继续显示不支持提示，保存原平台设置时不携带网络字段，不能误报固定网络已应用。
- 纵密配置、路由和 NAT 不在本次修改范围内。

## 状态与异常

只读区明确显示“保存时应用”的固定参数。只有设备回读的网卡、网关、DNS 与固定预设完全一致，同时网络已应用且无错误，才能显示固定出口已应用。旧自定义值或未配置状态应显示待应用，不能用旧源地址冒充固定出口。

保存失败保持草稿，要求重新读取状态；网络应用失败不得显示保存成功。原有修订检查、连接代次保护、令牌处理和平台启停行为继续有效。

## 验收

1. 先增加固定请求、旧自定义回读和旧设备兼容的失败用例，再实现。
2. 当前上位机每次保存固定提交 `interface_name=eth0.102`、`gateway=192.168.2.1`、`dns_servers=[]`，平台关闭时也成立。
3. 固定预设不可被一次请求或数组修改污染，不提供网络参数编辑入口。
4. 网络应用状态只根据设备回读判断，不能根据页面固定说明推断成功。
5. 执行相关工作流测试、前端构建和 ESLint。此次不部署或改动现场设备。

## 验证结果

固定预设及平台配置工作流 13 项通过；前端构建、ESLint 和差异检查通过。覆盖旧配置替换、平台关闭时仍写入固定出口、预设对象互不污染、旧服务兼容、保存响应不匹配及修订变化后的真实状态展示。未改下位机、协议或纵密代码，未操作现场设备。
