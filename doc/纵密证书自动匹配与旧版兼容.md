# 纵密证书自动匹配与旧版兼容

## 已确认目标

用户于 2026-10-24 确认实现并提交推送：默认自动匹配旧、新配套证书；旧版仅针对指定内置证书的精确指纹允许日期及名称兼容；账号认证只发送一次；提供自动／旧版／新版高级选择，显示实际匹配结果并细分网络、TLS 与认证错误。TCP 连接等待调整为 10 秒。

现场只读检查已确认，11.22.33.44:8888 的实际服务端证书与内置 old-trust DER 完全相同，SHA256 为 `e2292d0a9c31c6b9d1a1c07e1a2d743e5e291e3d7d5ae6c5ee47c3db3c4fffc0`，CN=server，无 SAN，2019-09-17 到期。当前客户端忽略旧组而只选新组，因此在网络连通后仍不能完成握手。

## 安全边界

- 旧版兼容只适用于固定纵密管理目标 11.22.33.44:8888，应用始终固定连接此地址及端口。
- Windows TLS 扩展必须在验证回调内检查服务端叶证书与批准的旧证书精确匹配，同时验证所配置 pin 本身具有上述固定 SHA256。不能仅匹配 CN、密钥、颁发者、链中任意证书或操作系统信任结果。
- 仅在精确匹配后，针对这张旧证书允许既有缺失 CA 的配套信任、日期及名称例外。再次执行 Windows SSL 策略检查，其余证书用途、签名及信任错误仍须拒绝；不能使用无条件成功回调或全局关闭证书验证。
- 撤销检查沿用原 Schannel 的缓存策略及撤销状态未知处理，不新增在线 CRL 请求；已知撤销必须拒绝，不能因为同一链同时存在到期或未知根问题而遗漏。
- 新版及用户自定义证书保留原严格验证，旧版扩展默认关闭，不影响其他 TLS 调用者；不写 Windows 证书存储或持久密钥容器。
- 新组候选明确配置批准配套信任证书中的逻辑服务名 `NARI`，仍由 Windows 严格验证名称、链和日期；这不是从未知服务端证书推断身份。网络目标仍固定 11.22.33.44:8888。旧组使用固定目标及专用 pin；自定义证书仍使用用户填写的服务器名称。
- 自动模式以旧组、新组为候选，先完成其中一组 TLS 验证，才允许发送登录报文。仅 TLS 阶段可切换候选，连接失败不重复认证；发送任何账号材料后不回退、不自动重试。
- 兼容策略仅在当前进程配置中有效，不按固定 IP 记忆设备；未知登录成功码继续保持未认证，不能为验证兼容而猜测成功应答。

## 接口约定

- 内置证书模式类型为 `auto | old | new`。`use_builtin_vertical_security_certificates` 接受可选 `request: {mode}`，省略时为 auto，继续兼容旧调用。
- CertificateProfile 新增可选 `builtin_mode`，builtin 来源返回当前模式；custom 来源不标记内置模式。
- CertificateProfile 的 server_name 在 new 模式为 `NARI`、old 模式为 `11.22.33.44`、auto 模式为 null，匹配前不声明候选的逻辑身份；不以此字段决定 TCP 目标。
- LoginResult 新增可选 `certificate_group: old | new | null` 及 `legacy_compatibility: boolean`，实际成功完成 TLS 后才填写组别，未知或失败的匹配不能冒充完成。
- 界面默认自动匹配，匹配前显示等待匹配；匹配后显示实际旧版／新版及兼容状态。高级选项可显式应用内置模式，沿用现有认证、检查和目标切换锁。
- 分别报告连接超时、连接失败、TLS 超时、证书不匹配、证书验证失败、其他握手失败、账号拒绝；脱敏日志记录阶段、候选组、稳定错误码及系统错误码，不记录账号密码、登录报文或私钥。

## 验收

1. 先补失败测试：默认 auto 含旧组、模式筛选、过期新组拒绝、旧版只限精确 pin、异证书及目标拒绝、日期／名称例外受限、认证只发送一次、发账号后不得切换。
2. Windows 兼容验证使用本地随机端口 TLS fixture；真实装置只允许无账号 TLS 握手核验，不下发配置、修改密码或自动尝试真实账号。
3. 页面覆盖自动默认、实际匹配标签、模式显式应用和失败状态、运行锁、认证请求不重复及原手动证书路径兼容。
4. 运行相关 Rust／工作流／离线测试、浏览器回归、构建、静态检查与 git diff --check，再按用户明确授权在 main 提交推送。生成物及诊断临时文件不进入仓库。
