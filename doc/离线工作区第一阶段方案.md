# 离线工作区第一阶段方案

## 1. 背景与目标

### 1.1 背景

上位机当前是下位机的在线控制台：全部 125 个后端接口经 Tauri 命令转发到 `ModuleManager`、`DataCenter` 与各业务模块的 gRPC 服务，本地只持久化 `mskdsp_manager_addr`、ModbusRTU/DLT645 的 MQTT 配置（`src-tauri/src/commands/app_storage.rs:17-19`）。没有下位机在线时：

- 协议页点表编辑被“必须先选中一条已加载连接”锁死（`src/pages/DLT645/components/PointTable.tsx:469-483`，选中来源是 `xxxListLinks()`）。
- 配置导出要求所选分区的模块全部处于运行中，否则整体失败（`src/utils/config-export.ts:905-916`、`:1533-1543`）。
- 各页面因接口失败持续报错并轮询（协议页 3-5 秒、实时值 500ms），界面不可用于配置。

现场目前只能靠脚本手工生成 `.mskcfg`/`jsonc` 再导入（参见 `现场点表/Calc配置/说明_mskcfg导入.md`）。

### 1.2 目标

- 新增“离线工作区”模式：不连接下位机也能够新建、载入、编辑、导出配置。
- 离线工作区可载入既有 `.mskcfg` 作为打底，可导出标准 `.mskcfg` 交现场导入。
- 离线模式下界面干净可用：运行态相关区域体面隐藏或显示中性值，不出现任何假数据，不出现误导性可操作按钮。
- 在线模式的行为与代码路径保持不变；离线逻辑与现有代码隔离。

### 1.3 本阶段不做

下发到设备（一键同步）留待第二阶段；本阶段的交付路径是“导出 `.mskcfg` → 现场导入”。

## 2. 术语

为避免与现场既有的“配置导入导出”混淆，本方案统一以下三个动作：

| 动作 | 方向 | 本阶段 | 实现位置 |
|---|---|---|---|
| 导入现有配置（`.mskcfg`） | 文件 → 离线工作区（替换当前工作区配置） | 支持 | 离线工作区菜单 |
| 导出 `.mskcfg` | 离线工作区 → 文件（交现场） | 支持 | 离线工作区菜单 |
| 下发到设备 | 文件/工作区 → 下位机 gRPC | 不支持（第二阶段） | 现场 `更多 → 配置导入导出`（现有功能，不改） |

离线模式**不复用**“更多 → 配置导入导出”的入口，避免用户把“载入工作区”误当“导入到设备”。

## 3. 非目标

- 不修改下位机协议、模块接口与 proto。
- 不实现一键下发、差异预览、三方合并与冲突处理。
- 不支持 IEC61850 与控制编排（两者不在 `.mskcfg` 分区内，`src-tauri/src/commands/export_config.rs:420-421`）。
- 不提供任何模拟/演示实时数据（明确不复用 `src/adapters/browser.ts:504-590` 的假值与假吞吐量）。
- 不引入全局状态管理框架，不做按页面的 ViewModel 重构。
- 不做“离线优先、双向同步”的影子库。

## 4. 设计

### 4.1 架构模式与隔离原则

采用“端口与适配器 + 策略 + 空对象 + 能力协商 + 声明式门禁 + 依赖注入”的组合：

| 模式 | 落地方式 |
|---|---|
| 端口与适配器 | `src/adapters` 中的 `api` 即端口；`tauriApi`（在线）与新增 `workspaceApi`（离线）是平级适配器 |
| 策略 + 代理 | `src/adapters/index.ts` 的 `api` 改为按当前模式分发的代理，页面导入方式不变 |
| 空对象 | 离线适配器对运行态接口返回中性值（已停止、空值），页面不需要“接口失败兜底” |
| 能力协商 | 新增 `src/offline/capabilities.ts`，以纯数据声明每种模式支持的能力 |
| 声明式门禁 | 新增 `<CapabilityGate need="…">` 组件与数据驱动菜单，页面不写模式判断 |
| 依赖注入 | `AppModeProvider` 通过 React Context 注入 `{ mode, capabilities }` |
| 导出策略 | 导出改为两个平级的 `ConfigExporter` 实现（在线读设备、离线读工作区），在线路径逻辑不变 |

隔离纪律：

1. 在线模式的进入条件不变：仍以 `hasTauriRuntime()`（`src/adapters/index.ts:159-161`）判定，离线只能由用户显式切换。
2. 对现有文件的改动只允许“新增分支/新增导出/新增注册”，不允许重写既有逻辑。
3. 能力开关默认全 `true`；在线模式下所有门禁分支恒不成立。
4. 离线逻辑全部位于 `src/offline/**` 与 `src-tauri/src/commands/workspace.rs`。

### 4.2 模式与能力矩阵

```ts
type AppMode = 'online' | 'offline';

type Capability =
  | 'config.read' | 'config.write'   // 配置读写（离线走工作区）
  | 'config.export'                  // 导出 .mskcfg（两种模式都支持，来源不同）
  | 'config.push'                    // 下发到设备
  | 'runtime.read'                   // 运行模块/链路/分组状态
  | 'runtime.control'                // 启停模块、启停链路/分组、对时、模拟值
  | 'realtime' | 'soe'               // 实时值、SOE 历史
  | 'module.ops'                     // 模块运维页
  | 'iec61850' | 'orchestrator'      // 未纳入 .mskcfg 的页面
  | 'local.*';                       // 设置、运行目录、更新包、纵密 SSH
```

| 能力 | 在线 | 离线工作区 |
|---|---|---|
| `config.read` / `config.write` | 设备 gRPC | 工作区内存快照 + 本地文件 |
| `config.export` | 读设备生成快照 | 读工作区生成快照 |
| `config.push` | 支持（现有导入） | 不支持 |
| `runtime.read` / `runtime.control` / `realtime` / `soe` / `module.ops` | 支持 | 不支持 |
| `iec61850` / `orchestrator` | 支持 | 不支持 |
| `local.*` | 支持 | 支持 |

### 4.3 端口选择

`src/adapters/index.ts` 由“二选一常量”改为分发代理：

```ts
export const api = new Proxy({} as typeof tauriApi, {
  get(_target, prop: string) {
    const impl = resolveApi();          // online → tauriApi，offline → workspaceApi
    const value = (impl as Record<string, unknown>)[prop];
    return typeof value === 'function' ? value.bind(impl) : value;
  },
});
```

- 浏览器开发模式（非 Tauri）仍使用 `browserApi`；离线工作区依赖 Tauri 文件读写与文件对话框，**仅桌面版可用**，浏览器预览不启用该模式。
- 代理必须保证在线模式下 `api.x === tauriApi.x` 的行为等价（启动时断言 + 冒烟测试）。

### 4.4 工作区文件（`.mskwsp`）

工作区文件为 JSON，`config` 段与 `FullConfigExportSnapshot.config`（`src/adapters/types.ts:1196-1228`）**完全同构**，以避免任何格式转换。

```jsonc
{
  "schema_version": 1,
  "workspace_name": "经开区二期",
  "created_at": "2026-05-20T10:00:00Z",
  "updated_at": "2026-05-20T10:30:00Z",
  "base": {
    "source": "device-snapshot",              // device-snapshot | empty
    "exported_at": "2026-05-19T08:00:00Z",
    "included_sections": ["iec104", "modbus_rtu", "data_bus"]
  },
  "conn_id_map": { "IEC104\u0000主站": 1, "ModbusRTU\u00001-1#": 17 },
  "next_conn_id": 100,
  "config": { /* 与 FullConfigExportSnapshot.config 同构 */ },
  "agc_control_profiles": [ /* 同构 */ ],
  "metadata": { "scope": "full", "included_sections": ["iec104", "modbus_rtu", "data_bus"] }
}
```

约定：

- 稳定键统一为 `module_name + "\u0000" + conn_name`（沿用 `src/utils/config-export.ts:947` 的 `connectionKey` 语义）。
- 载入部分分区的 `.mskcfg` 时，如实记录 `included_sections`；未包含的分区在工作区内为空集，导出时沿用 `metadata`。
- 导出时由 `workspaceToSnapshot()` 拼装出 `FullConfigExportSnapshot`，复用现有 `scopeConfigSnapshot` / `getIncludedConfigSections` / `buildExportFileName` 纯函数（需为这三个函数补 `export` 关键字，逻辑不变）。

### 4.5 离线适配器接口分层

| 类别 | 数量级 | 离线行为 |
|---|---|---|
| A 配置读写 | ~45 | 读写工作区内存快照；变更标脏，防抖 1s 落盘；关键操作立即落盘 |
| B 运行态只读 | ~25 | 返回中性值：链路/分组 `state=1`（已停止）、`last_error=''`、实时值与 SOE 为空 |
| C 运行控制 | ~20 | no-op，写中文日志，**不抛错** |
| D 本地能力 | 已有 | 原样保留（设置、运行目录、更新包缓存、纵密 SSH、`.mskcfg` 读写） |
| 其他 | 其余 | 抛 `OfflineUnsupportedError('离线工作区不支持：<接口名>')`，并写日志 |

关键约束：

1. **C 类必须 no-op 而非报错**。协议页保存链路/点表的流程是 `stopLink → 等 state≠2 → 写 → startLink`（如 `src/pages/ModbusRTU/index.tsx:281-317`），离线若 `stopLink` 抛错，保存会整体失败。返回 `state=1` 可让等待循环立即通过。
2. **B 类不得返回假数据**，只能返回“无数据”语义，由界面显示“—”或“离线不可用”。
3. **`config.export` 在离线模式下由 `workspaceExporter` 实现**，不经过 `assertExportModulesRunning`（`src/utils/config-export.ts:905-916`）；在线模式继续使用现有实现。

### 4.6 conn_id 稳定策略

页面大量使用 `conn_id` 关联（连接列表、数据总线、实时值订阅），离线模式必须自洽。下位机语义已核对确认：

- `conn_id` 由 **DataCenter** 唯一分配，按稳定键 `(module_name, conn_name)` 查表，未命中才取 `nextConnId_` 并自增（`MskDSP/src/DataCenter/CoreConnection.cc:124-165`）；分配发生在配置写入阶段（UpsertLink/UpsertGroup），不是 StartLink。
- 分配结果**单调递增、删除不回收**（`CoreConnection.cc:223-280`），`next_conn_id` 随 DataCenter 状态持久化，重启后按稳定键取回同一个 `conn_id`（`DataCenterGrpcService.cc:589-614`）。
- 模块侧容忍 `conn_id` 变化：IEC104 启动恢复时若与持久化值不一致，只打 warning 并回写（`MskDSP/src/IEC104/IEC104LinkManager.cc:515-519`）。
- 换设备导入时 `conn_id` 按建连顺序重新分配，因此**文件不得携带或复用旧 `conn_id`**。

离线工作区据此实现：

- 工作区维护 `conn_id_map`（稳定键 → 本地 conn_id）与 `next_conn_id`，分配后**跨会话不变**，删除连接不回收编号——与下位机语义一致，避免旧路由指向新连接。
- `dcListConnections` / `dcGetOrCreateConnection` / `dcGetConnTags` 由离线适配器按本地注册表实现，页面无需改动。
- 导出时剥离运行态 `conn_id`：路由端点只保留 `module_name + conn_name + tag`（复用 `stripRuntimeConnId`，`src/utils/config-export.ts:728-731`），由现场导入时重新解析。
- 已可复用的转换工具：`toDcRoute`（`:1459-1486`）、`waitForConnectionMap`（`:1437-1457`）、`resolveStableDataBusEndpoint`（`:647-673`）。

### 4.7 点表 → ConnTags 派生

`.mskcfg` 中的 `conn_tags` 会由现场导入流程真实写入 DataCenter（`src/utils/config-export.ts:1498-1503`）。DataCenter 侧不校验标签与点表是否一致（标签是独立注册表），一致性完全由各模块自身以 `replace=true` 全量推送保证；因此**离线导出的标签必须与下位机模块派生的标签逐字一致**——标签少了会被现场导入覆盖成错误注册表，并**静默剪除引用被移除标签的路由**（`MskDSP/src/DataCenter/CoreConnTags.cc:55-67`）。

派生规则已按下位机源码核对确认，实现为与适配器无关的纯函数：

```ts
deriveConnTags(moduleName: string, connName: string, config: unknown): string[]
```

| 模块 | 标签集合 | 下位机同步时机（对照） | 证据 |
|---|---|---|---|
| IEC104 | 点表全部 tag **＋ 对时标签**（默认 `__time_sync__`，可被 `time_sync_tag` 覆盖；已在点表内则不重复追加） | 启动恢复、UpsertPointTable | `IEC104LinkManager.cc:27-37`、`IEC104PointTable.cc:243-251` |
| ModbusRTU | 点表全部 tag（采集点与写功能码点不区分，取并集） | 启动恢复、UpsertPointTable | `ModbusRTUPointTable.cc:342-349`、`ModbusRTULinkManager.cc:2272` |
| ModbusTCP | 点表全部 tag | **仅** UpsertPointTable（恢复时不重建） | `ModbusTCPLinkManager.cc:227` |
| DLT645 | 点表 tag ∪ 块配置 items 的 tag（**不做任何拼接**，`block_di` 不派生命名） | 启动恢复、UpsertPointTable | `DLT645PointTable.cc:135-151,583-585` |
| AGC | 8 个固定中文默认点 ∪ 配置中的字面 tag（`p_cmd`/派生输出/成员量测与设定点及其 `base_tag`）；组名不参与拼接 | 启动恢复、UpsertGroup（tags 非空才推送） | `AGCGroupManager.cc:1302-1341`、`AGCDefaultPoints.cc:8-57` |
| AVC | 12 个固定中文默认点 ∪ 配置中的字面 tag（含 `q_total_cmd` oneof 分支） | 启动恢复、UpsertGroup（tags 非空才推送） | `AVCGroupManager.cc:1233-1278`、`AVCDefaultPoints.cc:8-83` |
| Calc | `<item_name>/result`、聚合项 `<item_name>/input_N`（**1-based**，N = 操作数个数）、非聚合项（含 `NOT`）`<item_name>/left_input` 与 `/right_input` | 启动恢复、UpsertGroup（tags 为空也推送） | `CalcGroupManager.cc:60-76` |
| DeviceInfo | 固定 2 个：`cpu.usage_percent`、`memory.usage_percent`（连接 `device-runtime`） | 模块启动 | `DeviceInfo.cc:23-24,112-120` |
| BoardIO | `DI1`–`DI4`（连接 `board-di`）、`DO1`–`DO2`（连接 `board-do`） | 启动注册 + 周期自愈 | `BoardIODataCenterClient.cc:22-23,133-138` |

规则要求：

1. 优先级：**以点表/配置推导为准**；载入的 `conn_tags` 只作初始种子与对照基线。不得沿用 `src/adapters/browser.ts:429-430` 那种“显式 conn_tags 覆盖推导”的语义（会导致改点表后标签陈旧）。
2. 点表或分组配置发生写操作后，相关连接的标签必须重算。
3. 输出按字典序排序（下位机以 `unordered_set` 存储、导出时排序，`CoreConnTags.cc:91-95`）。
4. 用现场真实 `.mskcfg` 的 `conn_tags`/路由作为黄金用例做对照测试。
5. 不覆盖 MQTTManager、ControlOrchestrator、ConfigPusher：前两者不在 `.mskcfg` 分区内，ConfigPusher 会在 `CONFIG_PUSHER` 模式下自行以 `replace=true` 下发文件标签，与本阶段并存时会产生竞争。

### 4.8 UI 行为规则

模式入口：`更多 → 工作区` 显式切换；首次连接下位机失败时提示“未连接下位机，是否进入离线工作区？”。

常驻状态条（离线时）：

```text
离线工作区：经开区二期.mskwsp   [未下发到设备]   [导出 .mskcfg]   [工作区 ▾]
```

| 位置 | 离线行为 |

| 数据总线 | 正常编辑连接标签与路由；隐藏实时值监视 |

| 轮询 | 全部运行态轮询（3-5 秒链路、500ms 实时值、2 秒控制组、5 秒设备指标、30 秒更新检查）在离线模式停止 |

### 4.9 导出流程与配置自检

导出步骤：

1. 选择导出分区（复用现有“选择要导出的模块”弹窗交互）。
2. 执行配置自检，按 `error` / `warning` 分级展示。
3. 生成文件，命名沿用现有规则：`<工作区名>-YYYYMMDD-HHMMSS.mskcfg`。
4. 展示“交付提示”（可复制）：文件名、包含分区、建议导入方式、导入前备份与地址核对提醒。

自检规则：

| 级别 | 规则 |
|---|---|
| error | 同一连接内 tag 重复；同一连接内 IOA/地址重复；路由端点 tag 未在 `conn_tags` 中声明；路由端点连接未在 `connections` 中声明；IEC104 连接标签缺少对时标签（`__time_sync__` 或配置的 `time_sync_tag`）；AGC 连接标签缺少 8 个固定默认点、AVC 缺少 12 个固定默认点；Calc 连接标签缺少 `<item>/result`、聚合项的 `input_N` 或非聚合项的 `left_input`/`right_input`；必填字段缺失（复用现有表单校验规则） |
| warning | 无点表的连接；点表已改动但标签可能未重算的连接；标签数量比打底快照减少（下位机以 `replace=true` 覆盖后会**静默剪除**引用被移除标签的路由）；路由自环（下位机不校验、允许自环，这里只提示不阻断）；工作区打底来源与时间；导出文件包含 MQTT 明文密码；现场若为 `CONFIG_PUSHER` 模式，导入结果可能被后续编排覆盖 |

自检为纯函数，可独立单测。

### 4.10 存储与运行目录

- 工作区目录：`<安装目录>\data\workspaces\*.mskwsp`；安装目录不可写时回退 `%LOCALAPPDATA%\com.mskdsp.upper\workspaces\`（与 `doc/打包与交付说明.md:114-118` 一致）。
- 新增 Tauri 命令：`list_workspaces` / `load_workspace` / `save_workspace` / `delete_workspace`。
- 写盘采用原子替换 + `.bak` 回退，模式与 `src-tauri/src/commands/app_storage.rs:105-184` 一致。
- 记忆上次打开的工作区（写入现有 `settings.json`）。

### 4.11 与下位机语义的对接约束

以下规则已按下位机源码核对确认，用于约束离线导出与“交付提示”的内容（现场导入流程本身不改）：

1. 平台侧点表/组配置写入要求链路或分组**处于停止态**，否则返回 `FAILED_PRECONDITION`（`IEC104LinkManager.cc:1314`、`ModbusRTULinkManager.cc:2255`、`DLT645LinkManager.cc:1512`、`ModbusTCPLinkManager.cc:223`、`AGCGroupManager.cc:474`、`AVCGroupManager.cc:379`、`CalcGroupManager.cc:1027`）。现有导入流程已做先停后写，本阶段只需在交付提示中提醒“导入前先停止相关链路与控制组”。
2. 点表写入 `replace=true` 为清空重建、`replace=false` 为增量合并；tag 或 IOA 冲突返回 `ALREADY_EXISTS`（`IEC104PointTable.cc:81-85,201-206`）。文件内的点表任务固定为 `replace=true`（`src/utils/config-export.ts:517` 等），交付提示需要说明覆盖范围。
3. 标签与路由的校验边界：连接已有 `conn_tags` 时，路由端点 tag 必须在其内，否则 `INVALID_ARGUMENT`；连接没有任何 `conn_tags` 条目时路由校验直接放行（`MskDSP/src/DataCenter/Core.cc:68-78`）。因此导出文件必须给出**完整**标签集合，不能只给增量。
4. 路由写入是原子的（全量校验通过才替换，`CoreRoutes.cc:11-38`）；自环不校验；同一目标允许多个源，但 `ExecuteCommand` 遇到一个源对多目标会返回 `AMBIGUOUS_ROUTE`（`CorePublish.cc:247`）。
5. 点表写入后是否需要启动链路：IEC104、ModbusRTU、DLT645 明确不自动启动（`IEC104LinkManager.cc:1353`、`ModbusRTULinkManager.cc:2291`、`DLT645LinkManager.cc:1555`），ModbusTCP 在点表非空时会自动启动（`ModbusTCPLinkManager.cc:230-238`）。交付提示建议“导入后统一显式启动链路”。
6. 模块自启动：`UPPER` 模式下 ModuleManager 按 SQLite 是否有记录自动启动 DataCenter/IEC104/IEC61850/ModbusRTU/ModbusTCP/DLT645/AGC/AVC/Calc（`MskDSP/src/core/ModuleManager/ModuleManager.cc:178-189,932`）；MQTTManager、ControlOrchestrator、BoardIO、DeviceInfo 不在清单内，需要显式启动模块。
7. `UpsertGroup` 会尝试自动启动控制组/计算组（`AGCGroupManager.cc:565`、`AVCGroupManager.cc:462`、`CalcGroupManager.cc:1108`），因此现场导入前后需要按现有流程处理停/恢复。

## 6. 异常场景

- 工作区文件损坏或版本不支持：拒绝载入并给出中文原因，保留文件不动，提供 `.bak` 回退。
- 工作区文件被外部修改：保存前比较 `updated_at`，不一致时提示覆盖或另存。
- 载入的 `.mskcfg` 分区部分缺失：按缺失处理为空集，并在界面上标注“该分区未包含”。
- 离线导出时自检出现 `error`：阻断导出并列出全部问题；`warning` 允许继续但需显式确认。
- 标签数量比打底快照减少：交付提示必须列出被移除的标签及其受影响路由，并说明现场导入后这些路由会被静默剪除。
- 现场导入时相关链路或控制组仍在运行：平台返回 `FAILED_PRECONDITION`，交付提示需提醒导入前先停止相关对象。
- 现场为 `CONFIG_PUSHER` 编排模式：文件中的标签与路由可能被后续编排收敛覆盖或清空，交付提示需提醒先确认现场编排模式。
- 切换回在线模式：以设备为准重新读取，工作区保持不变并明确提示“工作区不会被自动下发”。
- 浏览器预览环境：不提供离线工作区模式，入口置灰并提示仅桌面版支持。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 离线派生的标签与下位机不一致，现场导入后路由校验失败或标签被覆盖 | 规则已按下位机源码核对并固化在 §4.7；黄金用例对照；导出前自检阻断 |

| 在线路径被门禁改坏（隐藏了本该显示的按钮） | 能力默认全 `true`；门禁为声明式组件；启动断言 + 回归清单 |

| 工作区与设备配置长期不一致 | 本阶段明确“以设备为准”，工作区不作为下发来源；第二阶段再做差异预览 |
