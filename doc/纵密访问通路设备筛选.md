# 纵密访问通路设备筛选

2026-10-29 用户要求访问通路的平台设备选择器只显示当前账号有权限且在线的设备。

- 列表继续使用当前平台身份的 `remote_list_devices` 返回值；访问通路依赖 SSH 维护授权，进一步只保留 `online=true` 且 `allow_ssh=true` 的设备。
- 服务是否开放不等同于账号权限，不因缺少 `ssh` 或 `vertical-security` 服务隐藏已授权在线设备，继续显示原服务提示并限制对应操作。
- 刷新后所选设备离线、撤权或从列表消失，清空选择及旧检查结果，释放旧检查连接；读取列表失败也清除旧候选，避免继续使用无法确认的授权状态。
- 刷新过程中暂禁选择和远程配置／检查，空列表提示“暂无有权限且在线的设备”。不改变全局设备列表、纵密登录页、平台授权或后端鉴权。

验收使用真实页面与虚构 IPC：隐藏离线和未授权设备；保留已授权在线设备及服务提示；刷新后无效选择和旧检查结果清除；无候选时显示空态且不能执行远程操作。先保留旧实现失败证据，再实现并运行相关浏览器回归、构建和静态检查；不连接真实设备。

旧版新增回归在“离线设备不应出现在候选列表”处失败，实际出现一项，失败截图保留于临时目录 `mskdsp-device-filter-baseline`。原通路测试中的“选择未授权设备后按钮禁用”按本次需求改为“未授权设备不展示”，并用已授权但缺服务设备继续验证按钮禁用和切换清结果；原预期和失败记录一并保留。正常设备 fixture 补齐后端实际返回的权限及服务字段，不将缺失权限当作已授权。
