## 边界与实现

- 仅固定系统祖先目录允许 root:root 的组写权限，前提是所有者 uid=0、组 gid=0、无其他用户写权限、无符号链接及扩展 ACL，且通过 NSS 确认 root 组的主组／附加组成员全部为 uid=0。本轮支持的本机身份来源限定为 nsswitch 的 files 或 files systemd；带 LDAP、SSSD、未知来源或复杂分支动作的配置拒绝组写例外。该策略以受信本机 files/systemd 数据库为边界，不声明适用于任意 NSS 提供者。身份查询失败或结果不能验证时拒绝。
- 专属维护目录、脚本、ownership、unit、锁文件保持原有严格权限、归属、散列和单硬链要求；不修改 DSP 目录权限，不允许任意组写目录，不降低已有网络冲突检查。
- 固定诊断标记仅包含白名单代码，例如 directory_usr；后端只映射固定中文说明，不回传原始 shell 输出或凭据。
- 已确认前置阶段失败后，后续步骤使用 pending（未执行）；超时、断链或结果缺失使用 unknown（未确认）；unsupported 仅保留真实环境不支持，不能把未执行显示为不支持。
- 固定六阶段、逐步成功确认及失败单调性保持，所有修复用隔离命令桩和浏览器虚构 IPC 验证；不在真机应用或重启。

## 现场兼容补充

设备 `getent initgroups` 在查询成功且无附加组时只返回用户名；主组已从 passwd 单独核对，因此允许该空附组列表，仍拒绝空响应、错误用户名、失败退出和任何 gid 0 的非特权成员。正常 755 目录不触发 NSS 例外检查。

身份来源边界参考 [systemd 官方 nss-systemd 说明](https://www.freedesktop.org/software/systemd/man/248/nss-systemd.html)：该模块提供本机服务用户解析及 root/nobody 合成记录，也支持本机用户记录接口，因此本轮显式按受信系统来源处理，不能泛化为所有 NSS 模块均支持。
