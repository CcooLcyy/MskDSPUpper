# 下位机本地安装包导入方案

## 目标与范围

在软件更新的下位机页增加“导入本地安装包”，支持现有 `make_exe.sh` 生成的无扩展名 `mskdsp-<版本>` 自解压安装包。用户选择文件后，上位机读取包内 Docker 元数据，展示版本、架构、镜像摘要、包大小与 SHA256，用户再点击现有“下发并安装”。导入不会自动上传或安装。

## 输入输出与约束

- 输入为本地单个自解压安装包，必须包含精确的 `__ARCHIVE_BELOW__` 行及单个 MskDSP Linux 镜像归档；不接受裸 tar、任意脚本或其他产品镜像。
- 不执行安装脚本、不解压归档文件到磁盘，不依赖本机 Docker、Python 或联网。限制头部和单个元数据大小，拒绝重复元数据、路径穿越、多镜像、未知平台与摘要错误。
- 从 RepoTags 读取版本，从 Docker config 原始字节验证 SHA256 并取得架构。支持经典和 OCI Docker save 格式；OCI 必须验证 index、manifest、config 的关联及摘要。
- 导入包复制到上位机独立本地缓存，校验复制后的文件，成功后返回缓存清单及包路径。按内容摘要隔离，后台最新包下载及启动清理不得删除本地导入包。设置中的清理更新缓存可以清除全部导入包。
- 本地来源用清单可选字段 `local_import` 标记，沿用现有架构/通道结构（导入归入 CI 槽位，不表示该包由 CI 发布），页面明确显示“本地导入”。保留真实镜像版本，不根据文件名猜测。
- 自动切换到包的架构，选择状态锁定本地版本；自动检查结果不得覆盖本地清单、下载结果或安装镜像。切换架构、通道或主动检查更新可返回线上模式。
- 导入期间及部署期间禁止修改选择；异步操作在页面离开后不再应用。取消选择不改变现有目标，失败保留原选择。
- 安装继续执行现有 SSH 上传、sudo、安装前镜像检查及安装后镜像校验。缓存包 SHA256 与所选清单必须对应；本地来源无需再下载。

## 验收

Rust 单测覆盖经典/OCI 包、版本和平台识别、摘要链、错误输入、缓存保留及清理。前端测试覆盖本地选择不会混用后台下载结果，浏览器开发模式明确说明该能力仅桌面可用；执行工作流测试、离线测试、lint、构建及本地 Rust 测试。不连接或更新真机和服务器。

## 使用方式

进入“软件更新 → 下位机更新”，点击“导入本地安装包”，选择 `make_exe.sh` 生成的安装包（通常为无扩展名的 `mskdsp-<版本>`）。导入成功后自动识别 ARM64 / x64，并在“版本来源”显示“本地安装包”。确认“所选版本”和镜像摘要后填写连接信息，点击“下发并安装”。取消导入或导入失败保留原选择；选择线上通道或检查线上最新版本可以返回在线更新流程。

## 验证记录

- Node 工作流测试 362 项、离线测试 74 项通过；新增本地与线上包身份匹配测试，覆盖后台下载结果不能替换本地包。
- 前端 lint、TypeScript 检查和生产构建通过。
- Rust 下位机更新定向测试 61 项通过，包含 7 组本地解析及 2 组导入/缓存测试；验证经典和 OCI、ARM64 / x64、配置摘要、重复路径、截断层、超大元数据、导入失败保留源文件、重启保留缓存及清理行为。
- 浏览器预览已确认导入入口和仅桌面版可用提示；原生文件对话框与真机安装未实测，未修改任何设备。
