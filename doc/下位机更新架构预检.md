# 下位机更新架构预检

## 目标与边界

在传输下位机安装包前核对目标系统、CPU 架构与安装包真实架构，防止 x64 与 ARM64 误下发。覆盖密码/证书 SSH 直连、平台远程下发、在线下载/缓存/本地导入包及重试。检查不修改设备配置，不提供跨架构强制安装入口，不自动切换版本或下载其他架构的包。

## 输入输出与接口

- 新增 `get_lower_update_architecture`，使用现有目标连接参数，经本次下发同一 SSH 目标执行 `uname -s`、`uname -m`，返回 `os`、`architecture`（原始值）与 `platform`（规范值）。不需要 sudo。仅接受 Linux；`aarch64/arm64` 对应 `linux-arm64`，`x86_64/amd64` 对应 `linux-x64`。
- 上传参数增加必填 `platform`，表示本次选择并固定的包平台。后端解析安装包镜像配置元数据，核对包真实平台与请求平台，再通过同一目标连接查询设备平台。不依赖包名推断架构。
- 前端在查询运行镜像、上传和安装前先进入“检查设备架构”，展示设备与包平台；不匹配则显示双方架构并停止。后端上传预检独立执行同样的设备/包检查，防止直接调用上传接口绕过。
- 检测结果属于本次任务与固定连接，目标或认证变化后不得作为新连接的检测结果复用；每次下发或安装重试重新检测。上传后设备端安装器仍须在加载镜像、替换模块和容器前检查镜像配置平台与宿主机平台。

## 异常与日志

连接错误、超时、非零退出、缺少/重复/异常输出、不支持的系统或架构、无效包元数据、所选平台与实际包不符均拒绝继续。不匹配错误包含设备/包平台及选择匹配版本的提示。日志记录目标、检测原始架构、规范平台、包平台和结果，不记录密码。

## 验收与测试

1. 两种受支持架构及别名均正确规范化；不支持系统/架构、缺失或异常探测输出被拒绝。
2. 设备与包不匹配或探测失败时，前端不调用上传/安装，后端在任何包字节传输前拒绝；匹配时继续原流程。
3. 缓存与导入包同样读取包内平台；伪装文件名或篡改请求平台不能绕过后端。
4. 已上传包的重新安装仍进行新的目标架构检查；目标变化不展示先前目标的检测结果。
5. 设备安装器的架构校验在 Docker 加载、删除/替换容器及复制模块前执行；不匹配时这些动作均不发生，匹配时保持原安装行为。
6. 先补充失败测试，再实现；运行相关前端流程测试、Rust 单元测试、安装器 Python 测试及上位机构建/静态检查。无须连接或修改真机。
