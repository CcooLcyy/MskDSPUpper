# IEC104 连接状态显示方案

## 需求

IEC104 连接列表左侧状态点用于表示真实 TCP 会话状态，使用 `LinkInfo.connection_state` 渲染：

- `CONNECTION_STATE_CONNECTED (3)`：绿色，表示 TCP 已连接。
- `CONNECTION_STATE_CONNECTING (2)`：橙色，表示 TCP 正在连接。
- `CONNECTION_STATE_DISCONNECTED (1)`：红色，表示 TCP 已断开。
- `CONNECTION_STATE_UNSPECIFIED (0)` 或未知值：灰色，表示 TCP 状态未知。

`LinkInfo.state` 仍表示链路功能状态，继续由“运行中”“已停止”“待删除”等标签或文字呈现，不再用于决定左侧通信状态点的颜色。

## 范围

- 配置视图和 SOE 视图中的 IEC104 连接列表统一按 `LinkInfo.connection_state` 渲染左侧状态点及其悬浮提示。
- `LinkInfo.state` 继续用于“运行中”等功能状态标签、描述文字和操作可用性判断。
- 页面打开期间每 3 秒静默刷新一次 IEC104 连接列表，刷新时不显示全局加载态，不干扰当前配置操作。
- 当窗口重新获得焦点，或页面从隐藏恢复为可见时，立即触发一次静默刷新，无需等待下一个 3 秒周期。
- 连接列表刷新必须防止重叠请求；前一次刷新尚未完成时，定时器、焦点或可见性事件不得再启动新的刷新请求。
- 连接列表请求失败时保留配置和功能状态，但将已有通信状态标记为未知，避免继续显示可能已经过期的绿点或红点。
- 不修改 IEC104 协议定时器和后端断线判定逻辑，特别是不调整 APCI `t3` 参数及其 TESTFR 机制。

## 验收标准

1. `connection_state = CONNECTED` 时状态点为绿色，`CONNECTING` 时为橙色，`DISCONNECTED` 时为红色，`UNSPECIFIED` 或未知值时为灰色。
2. TCP 已断开但 `state = LINK_STATE_RUNNING` 时，状态点显示红色，功能状态仍显示“运行中”，两者不互相覆盖。
3. 配置视图和 SOE 视图的状态点颜色、悬浮提示与当前 `connection_state` 一致。
4. 页面每 3 秒发起一次静默刷新；窗口获得焦点或页面恢复可见时会立即刷新。
5. 在任意一次连接列表请求完成前，不会因定时器、窗口焦点或页面可见性事件产生并发的重叠请求。
6. 连接列表请求失败后，通信状态点显示灰色未知，配置和功能状态仍保留。
7. 修复不改变后端 `connection_state` 上报语义，不修改 APCI `t3` 参数或后端 TESTFR 断线检测机制。
