# 控制编排交互优化

## 范围与预期

本次仅调整控制编排上位机页面及其验收脚本，不变更下位机接口、控制顺序语义或其他配置页面。界面自有文案统一为中文，协议模块标识、连接名与点名保留原值。

- 最大化有助于查看表单；普通窗口也应支持编辑。弹窗正文在视口内滚动，标题和保存、取消操作固定可见。
- 点位选择只更新草稿。最终保存编排后自动建立触发路由和步骤输出路由，无需另去数据总线添加。未配置触发点的编排仅手动执行。
- 保存、删除、执行及路由重试分别显示忙碌状态，并防止异步请求完成前重复提交；执行期间保留执行对象，不能误用后来选择的编排。
- 配置已保存但自动路由同步失败时保留明确状态，允许单独重试路由同步。新建成功后切换为编辑状态，重试不能再次以仅创建模式提交配置。
- 执行结果在页面保留本次编排名、完成时间、响应或通信异常；失败时展示失败步骤、原因和命令状态。`executed_steps` 表示命令已被接受的数量，不能当成状态检查全部通过的步数。
- 步骤可上移、下移、复制及删除；总数维持 1 至 8，名称不得重复。固定值与使用触发值明确区分，高级超时、轮询和重试参数默认收起，展开不改变原配置。
- 校验错误就地提示并定位；点表读取失败与未注册点位分别说明。关闭未保存修改需确认丢弃，保存中不能关闭。

## 验收

通过真实 React 与 Ant Design 页面、虚构内存接口进行浏览器交互验收，不向设备下发命令。

1. 822×591 与 1920×1080 窗口均可直接访问保存、取消按钮，正文可滚动；英文默认空态、取消和类型标签改为中文。
2. 操作步骤后保存结果的顺序和值正确，复制不产生重复名称，第八步时禁用新增和复制；高级参数保留已有数值。
3. 草稿关闭时取消丢弃继续保留原输入；确认丢弃后关闭。缺失目标、重复名称或非法值不能写入接口。
4. 延迟执行响应时只收到一次执行请求；失败与通信异常结果常驻，显示具体编排和已有命令接受数量。
5. 选点但未保存时不写路由；保存时自动写路由。模拟路由失败后仍显示配置已保存，重试只同步路由，恢复后清除异常状态。
6. 某连接点表读取失败时提示读取失败和重试，不能直接误报未注册；刷新成功后可按原配置保存。

执行记录与失败截图由浏览器脚本输出到临时证据目录。源代码合约检查、前端构建和代码检查通过不代表设备控制链路已经验证。

浏览器验收入口为 `node tests/browser/control-orchestrator-ui.mjs`，需要可用的 Playwright 与 Chromium。已有外部依赖时可通过 `MSKDSP_PLAYWRIGHT_MODULE` 指定模块文件，通过 `MSKDSP_BROWSER_EXECUTABLE` 指定浏览器程序；依赖与截图无需写入仓库。
