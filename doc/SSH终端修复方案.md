# SSH 终端初始化与连接反馈修复

## 目标与范围

修复平台远程终端首次打开后黑屏、点击登录没有反馈的问题。保留现有明文平台隧道、密码认证、主机指纹核对及有界输入输出；只调整上位机终端挂载和会话交互，不改变设备协议、平台服务或运行中的设备配置。

当前弹窗延迟挂载内容，打开标志变化时终端节点可能仍为空。只依赖打开标志的 effect 不会在节点随后挂载时重试；登录处理又在没有终端时直接返回。主机指纹事件也可能早于打开命令返回会话 ID，确认动作需等待 ID 绑定并隔离旧会话回调。

## 行为与异常边界

- 以实际终端容器节点的挂载和卸载管理终端实例；首次延迟挂载、关闭重开及开发模式的重复 effect 均正确初始化和释放资源。
- 显示初始化、就绪、连接中、待核对指纹、已连接、已断开及失败状态。未就绪时禁用登录，初始化和连接错误持续可见，不允许静默返回或只依赖短暂消息。
- 连接前校验当前远程设备、在线状态和输入；重复点击不并发建立多条会话。设备切换、断开和弹窗关闭终止旧任务并清空密码。
- 指纹先到、会话 ID 后到时，确认按钮须等待绑定或可靠保留一次决定；不得丢失首次确认。确认成功或失败回调校验会话代次和 ID，不影响新会话指纹。
- 终端输入、输出额度和窗口变化沿用现有顺序与限制。终端文字、密码和认证载荷不写日志、工作区或测试产物；测试仅使用虚构凭据。

## 容器宿主机 SSH 使用说明

host 网络容器可以通过本机环回地址访问宿主机 SSH，无须在下位机业务容器里另装 SSH 服务。设备接入配置中的 SSH 端口填写宿主机实际端口，终端使用该宿主机的账号凭据；外部 SSH 转发端口或另一台实机的账号不能直接套用。

2026-10-21 的只读检查确认，Ubuntu 测试设备 test 使用 host 网络，宿主 SSH 在 22，daniel 账号存在；设备当时保存的 10022 无监听，megsky 不是该宿主账号。该记录不能作为所有设备的默认值，修复代码不自动改动运行配置；测试时由用户按目标主机实际配置调整。当前终端仅支持密码认证，本次没有验证宿主机是否允许该方式。

## 验收与验证

先补回归复现延迟节点挂载、关闭重开和指纹事件先到，再实现修复。实际 DOM 或浏览器验证覆盖弹窗首次打开可初始化、按钮状态、可见错误和关闭清理，不能以静态源码匹配或服务端渲染代替挂载验证。会话控制行为测试覆盖旧回调隔离、早到指纹与 ID 绑定、错误恢复及重复操作。执行工作流测试、离线测试、前端构建、严格 lint 和差异检查；提交推送后检查对应 GitLab 流水线直到结束，失败时定位并修复。

本轮不安装新依赖、不使用真实密码、不发起现场控制或 SSH 登录，不升级或重启正在运行的上位机和设备；用户在修复交付后进行现场测试。
