# 纵密维护通路与业务网络拆分

## 目标与边界（2026-10-26）

按已确认方案，11.22.33.44 的 101→108 维护访问统一由“纵密访问 / 配置纵密访问通路”管理。业务网络页面与生成、导出、部署的业务脚本不再配置维护地址、目标路由、代理 ARP、维护 SNAT，移除该页维护参数说明。业务侧仍独立启用所需 IPv4 转发，保留 107/108 业务地址、业务路由、PPP、DNAT、连接跟踪与现有业务服务。

本轮修改上位机源码与测试，不运行设备脚本、不登录纵密、不修改现场网络或安装本机程序。

## 独立维护持久化

维护入口保留固定目标、端口不限及现有严格冲突检查；SSH/sudo 只用于本次配置，不保存密码。运行态脚本和开机恢复复用同一固定脚本内容。独立 root 拥有的脚本与 systemd 服务负责开机恢复，服务依赖 network-online.target，失败每 15 秒持续重试（不因启动次数上限永久停止），不依赖 PPP 或业务服务，也不在业务脚本中调用维护配置。

安装前检查 systemd、路径安全、文件所有权与符号链接，不能覆盖不属于本功能的文件；写入采用同目录临时文件与原子替换。首次应用与服务启用均成功且逐阶段核验通过才返回已应用；失败如实报告，并尽力恢复本次文件、服务和网络变更，保留既有维护配置。重启恢复和手动配置使用同一把跨进程锁避免并发。全局 IPv4 转发属于共享依赖，不进行无条件关闭。

固定落盘位置为 `/usr/local/lib/mskdsp-vertical-security-access/apply.sh`、同目录 `ownership` 散列记录和 `/etc/systemd/system/mskdsp-vertical-security-access.service`，不复用业务服务或业务状态目录。仅安装和启用开机恢复服务，本次运行态已由同脚本验证，不重复启动服务；保留原服务当前运行状态。归属检查同时校验专用 marker、记录的脚本和 unit 散列、root 权限、单硬链及 systemd FragmentPath/DropInPaths/wants 目标。固定脚本通过 gzip/base64 ASCII 引导命令在 SSH 中传输，远端 pipefail 防止传输解压失败伪装成功。

## 接口与异常

沿用 configure_vertical_security_access_path 的固定目标、SSH认证请求，不接受用户传入命令、目标或接口。不改变账号登录协议或证书。结果固定为 preflight、addresses、routes、forwarding、verification、persistence 六阶段；阶段失败不会被后续成功覆盖，缺失或重复的成功记录、重复最终结果均不能返回 applied。缺失、服务未启用或写入失败不宣称完整成功。前端明确显示开机恢复行为，配置后仍由用户手动检查与登录，不自动提交账号。

业务新脚本不主动删除设备已有维护配置，防止迁移时断开访问；原已部署业务服务只有重新部署业务脚本后才会去掉旧维护逻辑。迁移顺序为先在维护入口应用并确认，再按需重新部署业务配置；本轮不自动执行迁移。

## 验收

1. 生成业务脚本不再包含维护网段命令、101接口依赖、代理ARP或固定维护阶段；业务路由和共享转发保持。
2. 维护配置重复应用、重启模拟恢复、接口未就绪重试与失败路径通过本地命令桩验证，不操作真实系统网络。
3. 缺少任一固定阶段不能返回成功；SSH和sudo凭据不进入日志或持久化文件。
4. 页面业务预览与维护窗口文案、阶段和互斥状态一致，前端构建与相关回归通过。

## 代理 ARP 范围修复（2026-10-27）

现场确认接口级 `eth0.101.proxy_arp=1` 与 PPP 默认路由组合，会使 DSP 代答其他内网地址的 ARP，并将收到的无关单播转发到 PPP。已确认的修复范围为上位机维护通路脚本、安装迁移及本地回归，不自动修改现场 DSP。

运行态只为 `11.22.33.44` 在 `eth0.101` 上添加显式代理邻居项，并将该接口自动 `proxy_arp` 关闭。首次应用、从旧版本重新应用及开机恢复使用相同逻辑；保留共享 IPv4 转发、业务路由和既有维护转发/SNAT 规则。安装流程继续原子更新脚本、服务及归属散列，用户使用新版上位机的“应用访问通路”即可完成设备配置迁移。

前置检查读取已有代理项及相关内核参数；全局自动代理或全局/101 接口的 PVLAN 代理已开启时，明确拒绝并在修改前返回原因，不擅自调整共享配置。代理邻居查询失败也不得当作空列表继续。已存在的目标代理项复用；新添加的目标项计入事务账本，后续失败仅删除本次新增项，并恢复修改前的接口代理参数。其他显式代理项不清空。成功前重新确认自动代理关闭、固定代理项存在及实际路由出口正确。

验收覆盖旧接口代理从 1 迁移为 0、首次配置、重复应用、IPv4 转发开启引起内核参数复位、既有代理项保留、代理读写及后续步骤失败回滚，以及重新安装后执行落盘脚本的开机恢复模拟。新增日志和页面结果使用中文，说明代理仅覆盖固定维护目标；命令桩验证与真实设备验证分别报告。

本次验证：运行态命令桩 18 项、安装事务命令桩 26 项、Rust 通路测试 11 项、工作流测试 553 项通过；前端生产构建、ESLint、Shell 语法、本次 Rust 文件格式及差异检查通过。修改前新增测试已复现旧行为。WSL Linux 隔离网络命名空间实测旧配置会代答无关地址；关闭自动代理并仅保留目标显式项后，维护目标 ICMP 往返通过，无关目标不再解析到 DSP 的 MAC。命名空间已清理；未向现场 DSP 应用配置或执行重启验证。

全库 `cargo fmt --check` 仍报告其他文件的既有格式差异，本次未批量修改；前端构建保留既有大分块提示。
