# 纵密默认密码修改与重新登录

## 目标与范围

用户于 2026-10-26 确认实现直连登录闭环：正常登录应答识别、默认密码与过期密码检查、同一 TLS 连接改密、使用新密码重新登录、只读初始化与会话退出。不改 DSP 网络、平台远程通道及其他纵密业务，不自动连接真实装置或实际修改装置密码。

## 证据与协议边界

- 现场原上位机 NSS3000 V1.1.E.4242 配置 `nuc980=1`；该认证模式与旧／新证书组独立，三种角色均使用 SM3(用户名+密码)。旧模式 UKey/PIN 不在本轮范围内。
- 完整抓包经离线解密、双向记录 MAC 与双方 Finished 校验：TLS 1.2 / TLS_RSA_WITH_AES_256_CBC_SHA256；登录应答命令 12、返回字段 17、LoginCount=0、isUpdatePwd=0、时间长度 14。证据只保留脱敏字段，不入库客户端登录明文、密码、摘要、私钥、会话密钥或完整真实抓包。
- 本轮仅接受实测返回字段 17 及完整合法资料结构；其他未知字段保持未验证，不推断完整成功码集合。默认密码提示来自原客户端本地摘要比较，不能用过期标志代替。
- 原程序 `MyMDI.updatePasString` 区分 admin/audit 与 secure 的默认密码摘要；新密码校验与 `ChangPwdPanel` 一致，改密命令 14 携带用户名及新旧 SM3(用户名+密码) 摘要，只有匹配命令 14 且结果 1 才认定修改成功。
- 原程序在改密后关闭旧界面／连接，用户需重新连接并输入新密码，随后下载 account.txt、读取 version.txt 并按角色初始化。本轮只读取这两份固定资料，不将其写到本地文件，也不接入配置下发等业务操作。

## 状态与接口

1. 登录请求校验目标、角色、用户名与请求标识，TLS 候选只在发送账号前切换；认证材料只发送一次。
2. 合法登录应答通过后检查默认密码和过期标志。需要改密时返回 `password_change_required`，包含与请求、账号、角色绑定的随机 `challenge_id`，不返回已登录会话；默认密码使用 `default_password`，过期使用 `password_expired`。
3. 临时改密连接及旧密码摘要仅保存在后端内存，有效期五分钟。取消、超时、证书切换、平台退出、页面离开与应用退出关闭连接并清除摘要。一个 challenge 只能提交一次改密，不自动重试。
4. 改密请求仍为 `changeVerticalSecurityPassword({challenge_id,new_password})`。后端再次校验长度、字符范围、复杂度及新旧不同；成功后关闭连接，返回 `changed=true`，前端清除所有密码输入并要求重新登录。失败、超时与取消同样消费临时连接，回到未登录状态；超时提示结果未确认，应先手动核实后再操作。
5. 无需改密时读取固定账号与版本资料，校验长度、UTF-8／严格 GBK 编码、固定八列结构、账号及角色；账号表辅助列不用于推断禁用或授权状态。全部成功后返回 `authenticated`，四个登录阶段均为 success，并保留真实 TLS 会话。初始化失败不建立身份。
6. 登录会话按账号、角色、目标和证书配置代次隔离；退出关闭实际连接。已认证连接十五分钟到期；断线、到期、取消全部或证书切换清除会话，切换证书开始时立即取消旧连接，不等待新证书加载成功。前端通过 `isVerticalSecurityLoginActive(connectionId)` 每三秒查询状态，该查询不续期。远程模式继续不可用。

## 前端交互

登录卡片切换到“设置新密码”，分别说明默认密码或过期原因；输入新密码及确认密码，无需重复输入原密码。提交前清空密码输入，改密期间禁止重复提交和切换目标。改密成功后返回原账号／角色的登录表单，提示使用新密码登录，不自动重新提交凭据。失败后不保留已失效 challenge。迟到的 challenge 与 session 均应清理，不能把旧请求结果绑定到新账号。
