# 平台远程纵密访问通路

## 已确认行为

2026-10-29 用户确认实现：在“纵密 / 访问通路”选择平台 DSP，通过远程 SSH 配置该设备的既有维护通路，再独立检测“上位机 → 平台 → DSP → 纵密装置”。配置与检测仅供上位机内部使用；纵密账号认证属于独立登录页，本轮不扩展远程登录。

三端实现契约见下位机 `doc/平台远程纵密访问通路.md`。远程检查使用固定服务 `vertical-security`，由下位机连接 `11.22.33.44:8888`；平台沿用 SSH 维护授权，不能只凭 gRPC 权限访问。普通模块服务仍限定本机地址。

## 页面与凭据

- 选择设备不改变其他业务页面的全局 DSP。设备未在线、缺少 SSH 维护权限或所需服务时，显示原因并限制对应操作。
- 远程配置只填写设备 SSH 用户名、SSH 密码和 sudo 密码，不填写设备现场地址。后端将请求中的 `device_id` 绑定到当前平台设备；不回退直连。
- 初次远程 SSH 身份信任沿用远程终端确认机制；未信任、身份变化时不执行维护脚本。密码操作结束或关闭窗口清空，不预填其他真机的密码。
- 配置复用现有 101/108 维护脚本及独立开机恢复服务。执行时锁定模式和设备；应用完成仍需手动检测，不能自动登录纵密。
- 检测展示设备授权/在线、平台通道、纵密 TCP 管理端口和 TLS 握手结果；只在实际管理连接探测成功时显示通过，不发送账号。
- 每次探测结束释放内部隧道，不建立电脑到目标 IP 的持久网络。成功仅表示本次管理通路检查通过；切换设备及重新配置应失效旧结果。
- 浏览器预览明确不支持实际设备配置和检测，不伪造远程成功。
