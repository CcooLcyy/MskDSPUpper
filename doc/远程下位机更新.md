# 平台远程下位机更新

## 使用条件

上位机已登录平台，目标设备已配置平台接入并在线，账号有该设备的 SSH 权限。设备宿主机需已有 Python 3.9 以上、systemd、Docker，且 SSH 账号能够提权执行安装。首次使用应通过远程 SSH 终端核对并确认设备主机指纹，更新复用同一信任记录。远程更新第一版使用 SSH 密码认证。

安装包必须由支持受管理更新的新版打包脚本生成；旧安装包会在设备侧预检拒绝，应重新构建发布。设备上已有的业务程序可以作为更新来源，但须符合标准容器布局并已具备平台接入能力。

## 操作与状态

在平台选择目标设备后进入软件更新页，核对设备和目标版本，输入设备 SSH 账号、密码及必要的提权密码，再提交更新。安装包经平台 SSH 隧道上传和校验，随后交给宿主机独立任务执行。

上传完成且宿主机受理任务后，即使业务容器重建、SSH 断开或上位机退出，宿主机任务仍独立执行。上传和受理前仍需保持上位机运行。等待设备重连不是更新失败；上位机会查询同一任务，超时显示暂时无法确认，用户应恢复查询而不是重新安装。

上位机只持久保存恢复查询所需的设备身份、任务编号及安装包标识，不保存任务密码。重新打开上位机后，恢复查询可能需要重新登录平台、输入设备认证信息。切换当前选择的设备不会改变已提交任务的目标。

## 自动回退和版本保留

新版本安装或本地健康检查失败时，宿主机恢复更新前镜像、配套模块和必要配置，保留日志，并检查旧版本恢复状态。平台或外网暂时不可达不作为回退条件。

“更新成功”“更新失败，已恢复上一版本”“回退失败，需人工处理”是不同结果。更新成功后稳定保留一个先前版本；准备候选版本时临时需要额外磁盘空间。不能以容器存在、设备在线或安装命令返回零单独认定更新成功。

## 第一版边界

仅支持当前标准安装器部署的单设备应用更新；无法可靠备份和恢复的自定义容器部署在修改前拒绝。自动恢复针对安装和本地健康检查失败，不承诺断电事务恢复、不兼容配置迁移、操作系统更新或批量升级。宿主机健康检查的实际覆盖范围、运行命令和本地验证记录以同工作区 `MskDSP/doc/平台远程软件更新与自动回退方案.md` 为准。

## 未受理任务恢复修复（2026-10-22）

现场包上传成功后，安装助手因 `/usr`、`/usr/local` 为 root:root 0775 而拒绝执行。助手尚未创建宿主机任务，本地却永久保留待确认记录；原查询还会安装助手、调和任务，并在任务不存在时重发旧包。

- 上传前通过 `preflightLowerUpdateTask(LowerUpdateRuntimeInfoRequest)` 检查 Python 3.9+、必需模块、systemd/Docker、sudo 及助手目录的完整祖先权限；检查不得创建目录、修改权限或启动安装。失败直接显示具体原因。
- 提交前的明确失败返回 `LOWER_UPDATE_TASK_REJECTED:`，只有能够证明宿主机未受理时才能使用；超时、断线或无法证明受理状态时继续保留原任务。
- `getLowerUpdateTask` 为纯查询：不安装助手、不创建目录、不写任务状态、不调和、不重新提交、不启动 systemd 服务。任务不存在返回 `LOWER_UPDATE_TASK_NOT_FOUND:`；查询仍绑定原平台和设备身份，权限异常不得伪装成任务不存在。
- 前端显示“原任务不存在”，保留恢复记录并提供“核验并结束本地记录”。结束前重新查询，确认原任务不存在、没有正在执行或回退失败的宿主机更新，并确认固定目标的业务容器正常运行且镜像 ID 有效。任一步失败均保留记录。结束不代表旧版本安装成功，不删除设备包或恢复材料。
- 结束前将非秘密恢复记录备份到本地归档，再调用独立的 `closeLowerUpdateTask(LowerUpdateTaskCloseRequest)`（查询字段加原包摘要和期望镜像）。该显式动作在宿主机受理锁内重新核验原任务不存在、设备无更新活动且业务容器健康，保存带 `closed: true` 的 `failed` 终态记录作为持久拒绝标记；新旧提交入口均在同一锁内读取已有终态，阻止迟到的 SSH 提交执行旧包。新版查询校验此关闭记录后按 NOT_FOUND 处理，仍保持纯读。标记成功后才清除本地占用；任何步骤失败保留记录，并允许幂等重试。未确认、已受理或回退失败任务不能通过此入口结束。新安装必须由用户另行明确发起，查询绝不重放旧包。
- 设备侧仅在核验属主、组及祖先目录后，收回 `/usr`、`/usr/local` 的组写权限；不递归 chmod，不修改其他服务与业务镜像。保留 root 独占检查。

验收先补失败测试，覆盖权限拒绝在上传前发生、明确未受理与回执丢失、重启后的纯查询、任务不存在不重发、结束记录的二次核验及备份失败保护。后端用实际生成命令验证无目录写入和无任务调度；现场仅验证环境预检与原任务不存在，不安装旧包。

验证结果：工作流 479/479、离线 101/101、Rust 更新任务定向 6/6，构建与严格 lint 通过。助手 Windows 隔离测试 45 通过、Linux flock 测试 1 跳过；WSL Linux 46/46 通过。独立审查执行真实旧版助手源码，确认关闭终态不调度安装；两仓 helper 摘要一致。

真机已通过只读环境预检；查询确认没有原任务、其他更新或安装进程后，使用原编号、包摘要与期望镜像写入显式关闭终态。原恢复记录已在上位机 `data/recovery` 备份。设备仍运行 p32 镜像 `sha256:7f42551094f661d01d85f393a242108a7056b06dc46af082f514b70e99fd8fa2`，容器启动时间未变，没有执行应用安装或回退。当前已安装上位机尚未替换，新查询交互需安装包含本修复的版本；旧版查询也能读取该 failed 终态以释放原本地记录。
