# 平台远程下位机更新

## 使用条件

上位机已登录平台，目标设备已配置平台接入并在线，账号有该设备的 SSH 权限。设备宿主机需已有 Python 3.9 以上、systemd、Docker，且 SSH 账号能够提权执行安装。首次使用应通过远程 SSH 终端核对并确认设备主机指纹，更新复用同一信任记录。远程更新第一版使用 SSH 密码认证。

安装包必须由支持受管理更新的新版打包脚本生成；旧安装包会在设备侧预检拒绝，应重新构建发布。设备上已有的业务程序可以作为更新来源，但须符合标准容器布局并已具备平台接入能力。

## 操作与状态

在平台选择目标设备后进入软件更新页，核对设备和目标版本，输入设备 SSH 账号、密码及必要的提权密码，再提交更新。安装包经平台 SSH 隧道上传和校验，随后交给宿主机独立任务执行。

上传完成且宿主机受理任务后，即使业务容器重建、SSH 断开或上位机退出，宿主机任务仍独立执行。上传和受理前仍需保持上位机运行。等待设备重连不是更新失败；上位机会查询同一任务，超时显示暂时无法确认，用户应恢复查询而不是重新安装。

上位机只持久保存恢复查询所需的设备身份、任务编号及安装包标识，不保存任务密码。重新打开上位机后，恢复查询可能需要重新登录平台、输入设备认证信息。切换当前选择的设备不会改变已提交任务的目标。

## 自动回退和版本保留

新版本安装或本地健康检查失败时，宿主机恢复更新前镜像、配套模块和必要配置，保留日志，并检查旧版本恢复状态。平台或外网暂时不可达不作为回退条件。

“更新成功”“更新失败，已恢复上一版本”“回退失败，需人工处理”是不同结果。更新成功后稳定保留一个先前版本；准备候选版本时临时需要额外磁盘空间。不能以容器存在、设备在线或安装命令返回零单独认定更新成功。

## 第一版边界

仅支持当前标准安装器部署的单设备应用更新；无法可靠备份和恢复的自定义容器部署在修改前拒绝。自动恢复针对安装和本地健康检查失败，不承诺断电事务恢复、不兼容配置迁移、操作系统更新或批量升级。宿主机健康检查的实际覆盖范围、运行命令和本地验证记录以同工作区 `MskDSP/doc/平台远程软件更新与自动回退方案.md` 为准。

## 未受理任务恢复修复（2026-10-22）

现场包上传成功后，安装助手因 `/usr`、`/usr/local` 为 root:root 0775 而拒绝执行。助手尚未创建宿主机任务，本地却永久保留待确认记录；原查询还会安装助手、调和任务，并在任务不存在时重发旧包。

- 上传前通过 `preflightLowerUpdateTask(LowerUpdateRuntimeInfoRequest)` 检查 Python 3.9+、必需模块、systemd/Docker、sudo 及助手目录的完整祖先权限；检查不得创建目录、修改权限或启动安装。失败直接显示具体原因。
- 提交前的明确失败返回 `LOWER_UPDATE_TASK_REJECTED:`，只有能够证明宿主机未受理时才能使用；超时、断线或无法证明受理状态时继续保留原任务。
- `getLowerUpdateTask` 为纯查询：不安装助手、不创建目录、不写任务状态、不调和、不重新提交、不启动 systemd 服务。任务不存在返回 `LOWER_UPDATE_TASK_NOT_FOUND:`；查询仍绑定原平台和设备身份，权限异常不得伪装成任务不存在。
- 前端显示“原任务不存在”，保留恢复记录并提供“核验并结束本地记录”。结束前重新查询，确认原任务不存在、没有正在执行或回退失败的宿主机更新，并确认固定目标的业务容器正常运行且镜像 ID 有效。任一步失败均保留记录。结束不代表旧版本安装成功，不删除设备包或恢复材料。
- 结束前将非秘密恢复记录备份到本地归档，再调用独立的 `closeLowerUpdateTask(LowerUpdateTaskCloseRequest)`（查询字段加原包摘要和期望镜像）。该显式动作在宿主机受理锁内重新核验原任务不存在、设备无更新活动且业务容器健康，保存带 `closed: true` 的 `failed` 终态记录作为持久拒绝标记；新旧提交入口均在同一锁内读取已有终态，阻止迟到的 SSH 提交执行旧包。新版查询校验此关闭记录后按 NOT_FOUND 处理，仍保持纯读。标记成功后才清除本地占用；任何步骤失败保留记录，并允许幂等重试。未确认、已受理或回退失败任务不能通过此入口结束。新安装必须由用户另行明确发起，查询绝不重放旧包。
- 设备侧仅在核验属主、组及祖先目录后，收回 `/usr`、`/usr/local` 的组写权限；不递归 chmod，不修改其他服务与业务镜像。保留 root 独占检查。

验收先补失败测试，覆盖权限拒绝在上传前发生、明确未受理与回执丢失、重启后的纯查询、任务不存在不重发、结束记录的二次核验及备份失败保护。后端用实际生成命令验证无目录写入和无任务调度；现场仅验证环境预检与原任务不存在，不安装旧包。

验证结果：工作流 479/479、离线 101/101、Rust 更新任务定向 6/6，构建与严格 lint 通过。助手 Windows 隔离测试 45 通过、Linux flock 测试 1 跳过；WSL Linux 46/46 通过。独立审查执行真实旧版助手源码，确认关闭终态不调度安装；两仓 helper 摘要一致。

真机已通过只读环境预检；查询确认没有原任务、其他更新或安装进程后，使用原编号、包摘要与期望镜像写入显式关闭终态。原恢复记录已在上位机 `data/recovery` 备份。设备仍运行 p32 镜像 `sha256:7f42551094f661d01d85f393a242108a7056b06dc46af082f514b70e99fd8fa2`，容器启动时间未变，没有执行应用安装或回退。当前已安装上位机尚未替换，新查询交互需安装包含本修复的版本；旧版查询也能读取该 failed 终态以释放原本地记录。

## 恢复查询等待与通信诊断修复（2026-10-23）

现场上位机已包含上一轮修复。原任务已关闭，直连运行同一只读查询约两秒返回不存在；平台恢复查询在设备 SSH 接受密码后、sudo/Python 执行前停滞，控制连接约 90 秒无接收后重连。现有前端最多 60 次重试且仅末次显示错误，导致最长约 93～103 分钟等待。当前证据不能确认平台程序、HTTP/2 或网络中的具体根因。

- 手工“恢复查询原任务”只读取一次原任务：得到终态按既有规则处理；任务仍执行时显示宿主机阶段，并结束本轮本地等待，允许稍后再次查询。第一轮出现连接、认证、授权、指纹、超时或解析错误即返回具体去密错误并保留原记录，不自动重试错误密码或长时间等待设备上线。
- 后端查询和预检总时限 30 秒，涵盖平台授权/目标解析、隧道建立、SSH 认证及查询响应；显式结束总时限 45 秒，为设备二次 systemd/Docker 核验留有限时间。提交总时限 600 秒，同样包含目标解析。前端只读查询设 35 秒兜底，防止 IPC 无回执。初次提交后的自动观测有 180 秒总预算，只有正常返回执行中状态才继续轮询；首个通信错误即交还用户处理。提交任务本身保持独立宿主执行语义，观测超时不等于安装失败。
- 只读观测期间提供“停止等待”：立即结束本地观测、保留原任务及恢复材料，不取消宿主机安装。停止后忽略迟到结果；旧响应不得清除记录或覆盖下一次查询。提交、上传及显式结束的写入阶段不显示该按钮，不能用停止等待绕过安全结束检查。
- 增加 INFO 级阶段及耗时日志：目标解析、SSH 连接、密码认证、会话通道、命令发送、sudo 输入、响应接收。超时/传输异常也必须在 WARN 记录失败阶段、任务编号和去密错误，不能只在 DEBUG 或最终轮次可见；不得记录密码、令牌、执行脚本或命令输入。
- 通信链路继续独立排查，使用只读日志/端到端观测定位；没有证据前不修改设备 MTU、路由或平台服务，不以延长超时掩盖停滞。若确认需要平台或下位机源码变更，先记录可复现输入、边界与测试后再实现。

先增加失败测试，再实现。覆盖单次恢复、首轮错误立即显示、非终态提示、总时限覆盖解析阶段、IPC 无回执、停止后迟到成功/失败、重复查询相互隔离、停止后仍阻止新安装、日志去密，以及现有未受理/不存在/回退失败/关闭终态保护。构建、lint、前端和 Rust 检查通过后再做只读现场验证；本轮不安装业务程序。

链路只读证据：平台运行提交 `978eb43`，匹配隧道的方向日志显示上位机至设备约 28526 字节已入转发队列，设备日志仅记录约 1090 字节到达；设备至上位机均约 2482 字节。实际平台链路走 `ppp0`，短时观察发现 RX 错误增长及 TCP 重传，期间接口重新创建，需与并行网络操作区分。此证据定位到平台至设备传输未完成，不能据此认定平台代码死锁或直接调整 MTU。本轮不修改平台服务、设备路由、PPP 或业务程序。

验证结果：先失败测试再实现，前端定向 53/53、完整工作流 491/491、离线 101/101、Rust 下位机更新相关 94/94 通过；构建、严格 lint、追加修改后的 TypeScript 与相关 ESLint 检查通过。独立审查补齐结束记录时运行镜像核验的 35 秒兜底，以及 Rust 解析先去密后裁剪的边界测试。停止等待不承诺立即取消已发出的后端只读 RPC，后端仍受 30 秒通信总时限约束；提交的 600 秒为通信阶段预算，不包含提交前 Stable 缓存校验。

用户已确认其他会话正在排查同一设备的网络，本轮将网络恢复留给该排查，不重复修改。真机只读复核仍运行 p32 且容器启动时间未变；上位机新逻辑尚未安装到当前运行版本，平台链路恢复后的端到端验证待网络稳定及安装本修复后进行。

## 同一设备的直连恢复与待确认任务入口（2026-10-23）

目标：平台隧道不可用时，用户可通过原设备的直连 SSH 查询同一个宿主机任务，并在确认任务不存在、设备无更新活动且业务容器正常后，沿用现有归档和显式关闭流程结束本地记录。切换页面所选设备或架构不会改变原任务身份；此次仍使用单个待确认记录。

- 原任务详情明确显示原平台、设备 ID、SSH 用户及任务编号。页面存在待确认记录时提前说明阻拦原因，提供“处理原任务”入口，避免点击安装后才显示泛化错误。
- 恢复入口支持“平台隧道”和“直连原设备”。直连地址由用户填写为 `原用户@主机:端口`，与原任务的 SSH 用户一致；不得填写 `remote` 或把当前页面另一台设备的表单自动带入。
- 请求保留原 `remote_target`、`upload_account`、任务编号、包摘要和期望镜像；仅查询、运行镜像核验和显式关闭可附加 `recovery_direct_account`。普通上传和提交仍走原有流程，直连地址不改写持久待确认记录，密码和本轮连接选择仅保存在内存。
- 直连连接建立时必须复用原平台和设备的持久 SSH 主机指纹信任记录，校验通过后才发送认证信息和命令。无信任记录、密钥变化、账号不一致或地址不合法均拒绝；不得自动信任直连主机，也不依赖当前平台登录、设备在线或当前页面所选目标。
- 直连只改变通信路径。查询仍为纯读；未知、执行中、回退失败及镜像不一致等既有保护继续生效。超时、停止等待、迟到回执不能清除待确认记录，所有连接错误去密后显示并记入日志。
- 直连确认更新成功后直接显示已确认结果，不为恢复业务连接再次等待故障的平台；提示用户恢复平台连接后刷新运行信息，不能自动连接当前页面另一台设备。
- 结束记录必须在本轮选择的同一路径重新查询原任务、核验业务容器和有效镜像、归档原记录，再在设备写入幂等关闭标记，最后清除本地占用。任一步失败仍保留原任务。不得以另一台设备的 NOT_FOUND 或仅凭设备在线解除占用。

验收采用文档、失败测试、实现的顺序。前端覆盖直连恢复的固定身份、用户校验、连接选择不持久化、查询和关闭链路一致、错误及迟到回执保留记录、关闭成功后允许用户新建任务；后端覆盖直连路由与原身份校验、无指纹及错误指纹拒绝、正确指纹放行、普通提交不支持恢复覆盖。继续运行既有任务核验与关闭保护的回归测试。本轮不安装设备业务程序、不清除现场记录、不修改设备网络或平台服务。

使用时点击“处理原任务”，在详情中选择“直连原设备”，填写原用户的实际 SSH 地址和原设备凭据后恢复查询。若返回“原任务不存在”，重新输入凭据并点击“核验并结束本地记录”；结束完成后才重新发起安装。原任务仍执行中或回退失败时继续保留记录，不能以切换连接方式跳过保护。

本地验证：前端恢复相关定向 65/65、完整工作流 529/529、离线 110/110、Rust 下位机更新相关 100/100、助手字节契约 1/1 通过；构建、严格 lint 和差异空白检查通过。真实环回 SSH 测试确认无原信任及错误指纹时密码认证计数均为零，正确指纹才放行，且不新增或改变信任文件。独立审查完成。构建仍有既有大分块提示。本轮没有安装新上位机或设备业务程序，也未使用新入口处理现场任务；安装包含本修复的上位机后仍需完成实际恢复验证。
