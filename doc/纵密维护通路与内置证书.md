# 纵密维护通路与内置证书

## 已确认范围

用户于 2026-10-24 明确要求：增加独立配置访问 11.22.33.44 的按钮，并将原纵密上位机对应的配套证书内嵌。不是执行原完整业务网络脚本，也不是新增任意目标 IP 的远程通道。

本轮仅修改上位机源码、内嵌资源和测试，不自动登录设备、配置 DSP 网络或下发业务配置。用户点击“配置纵密访问通路”后，通过其提供的 DSP SSH/sudo 凭据执行固定的维护通路脚本。纵密管理账号不用于 DSP SSH。

## 独立通路配置

入口放在纵密访问页的连接方式附近。打开独立窗口，展示固定目标、访问路径、当前运行态有效范围及 SSH 认证字段；不要求填写本端／对端六个业务地址。明确点击“应用访问通路”后才执行。

配置范围为 eth0.101 上的 11.22.33.1/32、电脑网段 11.22.33.0/24 的链路路由及代理 ARP，eth0.108 上的 11.22.33.2/32 和目标 11.22.33.44/32 的链路路由，以及必要的 IPv4 转发、仅针对上述源网段和目标的 FORWARD/SNAT 规则。保持端口不限，回程通过连接跟踪还原。不得清空地址、路由或防火墙，不设置默认路由，不修改 107 口、PPP、其他业务地址、DNAT 或现有完整配置服务。

先检查依赖、接口及目标地址／路由冲突，再做变更；重复应用不叠加规则。执行失败必须如实报告，并尽可能回退本次新增的配置；不承诺对任意系统状态的完整回滚。仅本次运行态有效，重启后需要重新应用；本轮不写开机服务。

启用全局 `net.ipv4.ip_forward` 可能同步改变内核的主机／路由器默认参数。失败时恢复该开关和本路径的代理 ARP，不保证恢复切换引起的全部内核默认状态；页面在应用前明确提示此影响。

后端固定脚本，不接受前端任意脚本、接口、IP 或端口。凭据通过现有 SSH 安全通道传输，禁止写入脚本、日志或普通设置。配置结果与可达性分开：配置完成不等于 ICMP、TLS 或登录成功。取消／卸载不能把仍在执行的设备变更说成已撤销；运行中锁定目标与模态窗口，执行结束后显示实际结果。

## 内置配套证书

用户已同意将原 NSS3000 配套的两组客户端身份嵌入程序：client.p12/tclient.jks 与 clientNew.p12/tclientNew.jks。准备脚本仅读取原始材料，在内存验证并转换信任证书与 PKCS12 资源，不输出原私钥、原证书口令或用户登录凭据，不改原文件。

默认在后端加载内置证书，前端只显示“内置配套证书”；手动配置移入高级选项，继续允许替换。客户端私钥及解锁材料随程序分发，不能声称安装包内的静态材料不可提取；它们不能替代纵密账号认证。原用户登录密码及 DSP SSH 密码均不得内置。

Windows 私钥导入继续使用现有 no_persist_key 补丁。默认自动匹配两组内置身份，旧／新两组最多在发送登录账号之前尝试对应 TLS 连接，不能在凭据错误后自动重复登录。新版及用户自定义证书继续严格校验证书链、有效期与名称；旧版仅对固定目标与已批准旧证书的精确指纹允许配套信任、日期及名称例外，不能全局关闭证书校验。具体边界见《纵密证书自动匹配与旧版兼容》。证书资源成功加载只代表本地配置就绪，不代表真实设备握手或登录成功。正常成功码集合仍留待真机确认。

实际核验结果：旧组客户端及信任证书于 2019-09-17 到期；新组有效期为 2022-03-28 至 2122-03-04。现场只读检查已确认装置提供的旧证书与内置旧组公共证书逐字节相同，故按用户确认增加受限兼容；不会将旧版例外套用到任意其他证书。两组公私钥及信任库完整性已离线核验；公有有效期元数据与实际资源一致。正常成功码仍待真机确认。

## 接口与验收

- 通路应用 API：`configureVerticalSecurityAccessPath({upload_account, auth, sudo_password})`。返回固定目标、applied、步骤、退出码及实际结果。仅桌面实现执行；浏览器开发模式返回不可用，不伪造配置成功。
- 证书 Profile 增加来源信息，保留原手动配置契约；默认由后端内置资源提供，前端不接触其私钥及解锁材料。
- 通路脚本用假命令／快照测试作用范围、前置冲突、重复应用和失败结果；不运行真实设备命令。
- 证书测试实际解析两组资源、检查证书对应关系与配置默认值；不导出私钥、不连接设备、不写 Windows 证书存储。
- 浏览器测试按钮、应用边界、秘密清空、运行锁、默认内置证书、替换入口，以及登录与检查互不伪装；执行相关工作流、离线、构建和静态检查。
