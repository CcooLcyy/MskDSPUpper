# 下位机缓存更新包复用方案

## 目标

上位机重启或重新进入软件更新页面后，恢复已下载且校验通过的下位机更新包，允许用户不访问在线更新源、不重复下载，直接将指定的已缓存版本下发到目标下位机。

## 范围

- 缓存更新包时同时保存完整更新清单和下载时间。
- 上位机提供查询、校验和恢复已缓存更新包的接口。
- 页面显示当前通道的已缓存版本，并提供“下发已缓存版本”入口。
- 保留现有在线检查、下载、上传、安装和安装后镜像确认流程。
- 本次不修改下位机安装包格式、更新源清单格式或下位机协议。

## 交互语义

“检查更新”用于从在线更新源获取当前通道的最新清单，它不是部署已缓存版本的前置条件。

“下发已缓存版本”按缓存清单中的确定版本执行部署，不表示该版本仍是在线更新源的最新版本。页面必须显示版本、镜像 ID 和下载时间；缓存未校验或已落后时显示相应的线上新鲜度提示。

缓存与线上版本的关系单独维护为以下状态，不与目标机运行镜像状态混用：

- 未校验：页面打开后尚未成功检查线上清单，或最近一次检查失败；提示缓存可能不是线上最新版本。
- 已确认一致：成功检查线上清单后，缓存清单的 `channel`、`platform`、安装包 SHA-256 和 `image_id` 均与线上清单一致；显示本次检查时间，并隐藏“可能不是线上最新版本”提示。
- 已确认落后：成功检查线上清单后，缓存包身份与线上清单不一致；显示线上版本信息，优先引导下载线上版本，仍允许用户确认后下发指定缓存版本。

“已确认一致”只表示截至最近一次成功检查时缓存与线上清单一致。CI 通道之后可能产生新构建，页面应显示检查时间，不能宣称永久最新。检查失败时不得推断缓存落后，只能显示无法确认。

## 缓存单元

每个通道和平台保留一个完整缓存单元：

- 经过 SHA-256 校验的安装包。
- 对应的完整更新清单。
- 下载完成时间。

缓存元数据使用独立 JSON 文件持久化，至少包含：

- `schema_version`
- `downloaded_at`
- `manifest`

元数据通过临时文件加原子替换写入。只有安装包下载完成且 SHA-256 校验通过后才写入元数据。

## 缓存恢复和校验

查询已缓存包时，上位机必须：

1. 解析并校验缓存元数据和更新清单。
2. 确认安装包为普通文件且文件大小与清单一致。
3. 重新计算安装包 SHA-256，并与清单比较。
4. 只有清单包含合法 `image_id` 时才返回为可下发缓存。

文件缺失、大小不一致、SHA-256 不一致、元数据损坏或 `image_id` 缺失时，不得恢复为可下发状态，并记录中文日志。

旧版本只保留了安装包、没有缓存元数据，无法安全恢复镜像 ID 和校验基准，因此不直接下发。用户完成一次检查和缓存命中后，上位机为该包补写元数据。

## 下发安全边界

使用已缓存版本只跳过在线清单检查和网络下载，不跳过以下检查：

- 上传前再次校验本地安装包大小和 SHA-256。
- 上传前查询目标下位机运行镜像，相同时跳过上传和安装。
- 安装接口执行命令前再次校验期望镜像 ID。
- 安装命令成功后查询运行镜像确认结果。

目标机运行镜像与缓存镜像不同时，上位机无法仅通过镜像 ID 判断新旧，页面需要在下发前显式确认按指定缓存版本继续。

## 接口设计

上位机新增一个无副作用的 Tauri 命令，按通道返回已校验的缓存更新包。返回值包含完整清单、本地包路径、实际文件大小、实际 SHA-256 和下载时间。没有可用缓存时返回空值，不将“无缓存”视为异常。

下载命令在缓存命中或新文件下载完成时统一写入缓存元数据，使旧版本缓存可在一次检查后自动升级为完整缓存单元。

## 缓存清理

启动清理以“安装包 + 元数据”为整体：

- 继续删除未完成的 `*.download` 文件。
- 每个通道和平台只保留元数据指向的安装包和元数据文件。
- 删除其他旧安装包、孤立元数据和临时元数据。
- 手动清理缓存时同时删除安装包和元数据。

## 异常处理

- 元数据不支持或损坏：忽略该缓存并记录警告，页面仍可在线检查。
- 安装包缺失或不是普通文件：忽略该缓存。
- 文件大小或 SHA-256 不一致：标记缓存无效，不允许下发。
- 缓存校验期间文件被清理：在同一缓存锁内完成查询和校验。
- 直接下发前目标镜像查询失败：不继续上传。

## 验收标准

- 下载或命中缓存后，重启上位机仍能查看并选择该已缓存版本。
- “下发已缓存版本”不请求在线更新源，不重复下载安装包。
- 下发前重新校验本地安装包和目标运行镜像。
- 目标已运行相同镜像时，不上传、不执行安装命令。
- 缓存包损坏或缓存清单缺少有效镜像 ID 时，不允许直接下发。
- 用户可以继续使用原有“检查更新 -> 下载到上位机 -> 下发并安装”流程。
