# 配置导入导出第一阶段方案

## 目标

在“导出前相关模块均已启动”的前提下，补齐 Calc、AGC 和 DataCenter 的可迁移配置，使上位机的 `.mskcfg` 文件能够在同一协议版本的目标环境中完成导出、导入和再次导出。

停止模块但已落盘配置的读取、IEC61850、ControlOrchestrator 暂不在本阶段处理。

## 范围

### Calc

- 导出全部计算分组及其计算项、操作数、常量和小数位配置。
- 导入支持覆盖和合并两种模式。
- 覆盖模式删除文件中未声明的旧计算分组；合并模式保留旧分组。
- 导入后恢复导入前处于运行状态的同名计算分组。

### AGC

- 保留现有控制组导出。
- 为每个控制组导出已确认的固定控制参数 profile，包括 P/I、偏置、积分限幅、步长和爬坡限制等。
- 导入 profile 前停止运行中的控制组；配置与 profile 写入完成后恢复原运行状态。
- 未确认 profile 使用缺省/零版本语义，不强制生成新的确认记录。

### DataCenter

- 导出稳定连接主键（`module_name` + `conn_name`）、连接标签注册表和路由。
- 不把运行时 `conn_id`、`next_conn_id` 作为跨设备稳定标识；导入时按稳定连接主键重新解析连接 ID。
- 导入顺序为：确保连接存在、覆盖/合并标签、最后写入路由。
- 覆盖模式清理目标态之外的路由；合并模式保留既有路由。

## 运行前提

- 全量导出时，Calc、AGC、DataCenter 以及当前已纳入导出范围的协议模块必须处于“模块进程运行中”。
- 模块未运行时导出直接失败并给出中文错误，不返回空配置。
- 不自动启动模块，避免触发控制组、计算分组或协议链路的内部功能启动。

## 文件兼容

- 扩展 `ConfigExportSectionId`、快照类型和 protobuf 映射。
- 读取旧 `.mskcfg` 时，缺少新增字段按空集合处理。
- 新文件的元数据必须声明实际包含的分区；模块级导出只能选择已支持分区。

## 验收标准

1. 运行中的 Calc 分组、AGC profile、DataCenter 标签和路由导出后，导入到干净环境能够恢复相同配置。
2. 覆盖/合并模式的删除、保留和同名处理符合现有导入语义。
3. 任一必需模块未运行时，导出显示明确错误且不生成空配置文件。
4. 旧格式文件仍可读取；未实现的 IEC61850、ControlOrchestrator 字段不在本阶段引入。
5. 新增逻辑有确定性测试覆盖，并保留中文日志记录导出、导入和失败原因。
