# Modbus 点表模板

## 目标与边界

Modbus RTU/TCP 连接均可以从同一模板目录预览、勾选和添加点位。模板只提供点位，不改变 IP、串口、从站地址或轮询状态。应用将点位复制到连接已有配置，经现有保存接口提交；禁止覆盖已有点位，模板升级不修改已应用配置。

## 文件与持久化

内置 JSON 位于 `src/features/modbus-templates/builtin/`，通过 Vite 静态打包离线使用。模板包含版本 1、ID、厂家、型号、协议版本、0/1 基地址、说明、来源文件 SHA256，以及点位名称、实际功能码、地址、类型、长度、十进制倍率/偏移/死区、字节序、位索引、单位、分组和来源页。

个人模板通过现有上位机设置 adapter 存入 `protocol.modbus.templates.personal`；桌面版使用原子写入的 settings.json，浏览器开发版使用既有 localStorage 设置 adapter。个人模板与内置模板隔离，禁止 ID 覆盖；导入、导出均为版本化 JSON。保存当前连接时保留精确十进制字段，未存储的单位/分组留空，不臆造设备资料。

## 输入规则与应用

导入限制 2 MiB，每个模板最多 2000 点，个人模板最多 100 个且持久化总量限制 10 MiB。所有对象字段强校验，拒绝未知字段、重复点 ID/标签、错误功能码/类型/长度组合、地址溢出、不合法或非有限十进制、非法位索引和字节序。模版的实际功能码转为现有 API 枚举；模板地址先归一为协议偏移，再换算到目标连接的地址基准。

默认勾选无条件可读点，写点需用户主动选择；条件点记录适用条件，并通过 `default_selected: false` 默认不选。预览展示加前缀后的最终标签、换算后地址及冲突理由。标签重复优先判冲突；同功能码寄存器范围重叠判冲突，但相同寄存器、相同长度、不同位索引的 BOOL 点可以共存。已勾选点间也校验冲突，同批重叠点双方标记冲突；应用自动跳过冲突行并显示跳过数量，其他无冲突点正常添加。用户选择后提交前再次按最新点表校验。

枚举遥信使用可选 `enum_value`，限定 BOOL 和 0x03/0x04，与 `bit_index` 互斥，0 是有效值；1/2 寄存器按端序归一化后执行完整无符号原始值相等比较。同地址、同长度、相同解码序、不同枚举值的 BOOL 点允许共存，整字/位点/重复枚举及部分重叠继续判冲突。模板预览与连接点表显示相等值，RTU/TCP 编辑器可选择解析模式及端序，个人模板导入导出保持字段，旧点缺省和新接口 null 在保存快照中等价。枚举解码需配套下位机支持，不能用位索引代替。

## 异常与验收

标签前缀输入最多 256 字符；非法或过长前缀在预览中标记冲突并禁止添加，不向页面渲染层抛异常，修正输入后可继续使用。

RTU 已启用显式批量读取时，模板应用根据停止后复读的最新连接配置，仅为新增且未覆盖的寄存器读点追加完整区间，保留原手工区间和其他配置；双寄存器点不拆开，每区间最多 125 个寄存器。先保存补齐后的读取策略，再保存点表；点表保存失败时恢复原策略，恢复失败明确报告两项错误。两次接口调用处于同一停止/恢复周期。逐点模式保持原策略，线圈与写点不加入寄存器区间。RTU/TCP 保存前均复读实际运行状态，并将该状态传入同一次停止/恢复周期，避免依据旧页面状态误停或误启连接。

内置或个人模板损坏不静默使用：目录加载给出具体错误。保存失败保留现有设置快照；并发个人模板增删按队列串行持久化。模板应用保持连接原停止/运行状态；运行中的连接先暂停轮询、保存后恢复。保存前复读连接地址基准和点表，变化时刷新并要求重新核对，避免旧快照覆盖；兼容旧点表空十进制原文字段。测试覆盖实际功能码映射、0/1 基边界、倍率原文、重叠及位点例外、写点默认不选、导入恶意/损坏数据和个人模板存储事务边界；桌面设置键与 Rust 白名单通过既有回归检查。

## 当前模板库与验证

内置模板包含「华为 SUN2000 三相 · V3.0」和「阳光电源光伏逆变器 · V1.1.78」。华为共 101 个条目（32 个普通只读点、61 个 BOOL 遥信点、8 个写控制点），依据 2021-04-21 版 V3.0 文档生成。阳光共 73 点（28 个测量及反馈点、37 个 BOOL 状态点、1 个故障码点、7 个写控制点），依据 2024-09-14 版 V1.1.78 文档生成，具体范围及兼容要求见《阳光电源逆变器模板》。其他华为版本及奥太、古瑞瓦特、固德威模板均已从内置目录删除。来源文件、哈希及页码继续保留，用户自行保存或导入的个人模板保留。模板中的单位用于预览核对；当前连接点表接口未记录单位，保存为个人模板时不推断单位。华为适用及排除范围见《点表模板-固德威与V3核对》，其他厂商核对记录仅作为历史资料。

按用户选定范围，删除控制策略参数 40037、40038、40196、40198、42015、42017、42019，以及设备配置参数 40000、42000、43006。保留功率调节及开关机控制 40120、40122、40123、40125、40126、40129、40200、40201；前六个由参数读回改为写控制，不额外生成读回条目。单寄存器采用 0x06，两个寄存器采用 0x10，依据源文物理第 72、75、77 页的功能定义。保留原地址、数据类型、寄存器数、倍率、单位、字节序与来源信息；写点统一分组为“控制设置”、默认不选，不加入采集读取区间。适用条件继续提示机型、固件、权限和 32 位字序限制。模板调整不自动删除或改写已应用到连接的点表。

用户进一步要求删除全部 48 个 PV1~PV24 电压、电流点，并将状态1~3、告警1~3 的每个已定义位独立建为 BOOL 遥信。替换原有 6 个整字点，不同时保留同地址整字与 BOOL 位点，避免已有点表的地址冲突规则拒绝保存。状态1（32000）拆为 Bit0~9 共 10 点；状态2（32002）拆为 Bit0~2 共 3 点；状态3（32003，占 2 个寄存器）拆为 Bit0~1 共 2 点。告警1（32008）和告警2（32009）各拆为 Bit0~15 共 16 点，告警3（32010）拆为 Bit0~13 共 14 点，不生成保留位。全部遥信仍使用 0x03，按字节序、字序解码后以 `bit_index` 提取单个位；同字内不同位共享地址及寄存器长度，读取区间可合并。状态定义来自物理第 18 页，告警位定义及模块适用条件来自第 48~50 页。

状态2 Bit0 命名为“非闭锁状态”，明确 0=闭锁、1=非闭锁，不用倍率伪造 BOOL 反相。状态1 Bit8 命名为“关机状态”，与写控制“关机”区分。状态3两个点继承原 32 位字序须现场核对及默认不选条件；告警表脚注涉及选配功能的点记录对应条件并默认不选。32089“设备状态”是枚举，继续保留整数，不按位拆分。其余 32 个普通 RO 点完整保留内容与顺序，全部清单附后供用户继续裁剪。

浏览器验证：RTU 一基地址转换及保存后保持停止；TCP 停止状态保存后仍停止、运行状态追加点位后恢复运行；已有点位重复应用自动跳过；个人模板保存后刷新仍存在。独立试用入口复用正式模板组件，但连接点表仅在内存，不访问设备。尚未进行真实设备互操作验证。

首次功能完善验证：工作流测试 343 项、离线测试 74 项及相关 lint、构建通过。正式浏览器模拟页验证 TCP 停止时添加 23 点保持停止、运行时追加 22 点恢复运行；RTU 一基地址转换正确，原 4 个批量区间保留，追加后 11 个区间覆盖 45/45 点并恢复运行；超长前缀可纠正且不再触发渲染异常。Rust 103 项回归此前已通过，该轮仅修改前端应用流程，未重复运行 Rust；未在桌面安装包或真实设备上进行通信验收。

模板库精简验证：30 项模板相关工作流测试及生产构建通过；目录测试明确要求仅包含指定华为文件、厂家和名称正确、104 个条目，防止其他内置模板被重新收录。

控制范围裁剪验证：32 项模板相关工作流测试、测试文件 ESLint、生产构建及 `git diff --check` 通过。回归锁定 10 个删除地址不存在、保留 8 个控制点的写功能码与默认不选、原 86 个采集点的完整内容及顺序不变，并使用实际应用及读取计划保存逻辑验证控制点不生成采集区间。本轮仅调整内置模板与说明，未进行真机控制验证；当时按用户要求保留在工作区供审阅。

遥信展开及 PV 裁剪验证：34 项模板相关工作流测试、测试文件 ESLint、生产构建及 `git diff --check` 通过。测试核对 61 个遥信的名称、地址、位索引、寄存器长度、来源页码和条件默认不选，校验位索引 15/31 的合法边界与 16/32 的越界拒绝，并验证同字位点可共同应用、读取区间合并、一基地址转换及端序保留。独立从 Git HEAD 核对其余 32 个普通 RO 点，完整内容与顺序一致。本轮验证覆盖模板配置与应用逻辑，未进行真实报文或设备联调。
