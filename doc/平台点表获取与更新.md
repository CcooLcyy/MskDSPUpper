# 平台点表获取与更新

Modbus RTU/TCP 点表模板统一来自已登录的平台，上位机不再携带内置模板、个人模板库或模板文件导入入口。原厂家模板仅作为测试样本保留在 `tests/fixtures/modbus-templates`。

登录平台或平台恢复连接时自动检查目录，有变动时提示；不需要先连接下位机。连接下位机后打开“平台点表模板”，读取该设备的实际点表、连接配置、版本和模板来源，再加载平台模板并预览。

- 新应用可以选择采集点及标签前缀，写控制点和条件点默认不选。
- 已应用模板默认展示更新差异。未改动的采集点修改默认选中，现场改过的点显示冲突并默认保留；平台删除的点默认保留。
- 勾选冲突项表示明确采用平台配置，勾选删除项表示明确移除现场点位。详情提示同时显示现场配置和平台配置。
- 每个应用记录独立的应用 ID、平台、模板 ID、完整版本、原始模板快照、前缀，以及源点位 ID 到现场标签/基线的映射。现场改名迁移目标标签，保留原基线，因此后续仍能识别现场修改。
- 只推进明确接受点位的基线。跳过新增、删除或冲突时保留未处理差异，不宣称整张模板已更新。初次应用时未选择的既有模板点不会被下次检查误报为新增。
- 同模板允许多次应用，但每次所选点位仍需通过原有标签及地址重叠检查；不同前缀不能绕过寄存器冲突。

桌面模板保存通过单次固定设备事务执行：验证打开窗口时的设备代次、完整连接配置、点表和来源版本；保持运行状态，RTU 补齐读取区间，原子保存点表与来源，失败时按配置版本保护回滚。旧下位机返回版本 0 时明确拒绝模板应用，现场普通点位编辑仍可使用。

本地缓存仅接受平台响应，固定设置键为 `protocol.modbus.templates.platform-cache`，内部按平台地址隔离，总量最多 50 MiB。缓存不足时淘汰较早记录；只有连接失败、超时或服务暂时不可用才可使用缓存，并明确显示版本可能过旧。登录过期、权限拒绝、模板删除或非法内容不能回退缓存。缓存写盘失败不阻断已成功获取的合法响应。注销及平台切换期间的迟到响应不会写入缓存或更新窗口。

配置导出保留 `template_bindings_json`；导入在目标连接读取实际版本并通过 CAS 保存。合并导入沿用现有连接重命名规则，来源跟随新连接；离线手工编辑也保留原来源字段。来源缺失时不会猜测现有点位所属模板。

点位比较与下位机 Decimal20 规范对齐：用整数精确处理 20 位小数及半数远离零舍入，支持科学计数法和固定小数回读，保留真正的高精度差异；同时处理倍率零默认值及类型相关的寄存器数、字序、字节序，避免产生假冲突。

可输入十进制字符串版本号读取指定历史版本，或返回当前版本。历史内容明显标记，应用前再次确认；不会因旧缓存自动回退设备。模板仅修订版本或说明、点位无差异时，可以“确认版本信息”原子更新来源记录，现场点位保持原值。复制 RTU/TCP 连接时，来源记录跟随点表复制并使用目标设备版本保护。
