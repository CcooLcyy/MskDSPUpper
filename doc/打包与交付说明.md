# 打包与交付说明

## 目标

- 用统一脚本把 `Tauri NSIS` 产物收敛为可分发、可校验、可排障的交付物。
- 为现场部署保留安装、启动、停止、升级、版本检查、日志探测等最小运维动作。

## 范围与非目标

### 范围

- `package/staging` 和 `package/out`
- 交付 zip、symbols zip、校验文件
- PowerShell 安装与运维脚本

### 非目标

- 不生成 Docker 镜像
- 不生成 Linux/macOS 包
- 不构建移动端（Android/iOS）产物，因此 `src-tauri/Cargo.toml` 的 `[lib]` 只保留 `lib`（rlib）crate-type，不再保留 Tauri 脚手架默认的 `cdylib`/`staticlib`；如将来需要移动端或对外 FFI 产物需再补回

## 输入输出

### 输入

- `dist/`
- `src-tauri/target/**/release/bundle/`
- `src-tauri/target/**/release/*.pdb`
- `scripts/workflow/templates/*.ps1`

### 输出

- `package/out/<channel>/<platform>/<artifact>.zip`
- `package/out/<channel>/<platform>/<artifact>-symbols.zip`
- `package/out/<channel>/<platform>/<artifact>-SHA256SUMS.txt`

## 生成方式

1. 生成构建元数据：

```bash
node scripts/workflow/emit-build-metadata.mjs --channel beta
```

2. 为当前渠道应用预发布版本：

```bash
node scripts/workflow/apply-channel-version.mjs --metadata-file package/build-metadata.json
```

3. 渲染 CI 专用 Tauri 配置：

```bash
node scripts/workflow/render-tauri-config.mjs --metadata-file package/build-metadata.json
```

4. 产出 Tauri 安装包：

```bash
npx tauri build --bundles nsis --target x86_64-pc-windows-msvc --ci --config package/generated/tauri.ci.conf.json
```

5. 收集到统一 staging 目录：

```bash
node scripts/workflow/stage-release.mjs --metadata-file package/build-metadata.json
```

6. 生成交付包与 checksum：

```bash
node scripts/workflow/create-delivery-bundle.mjs --metadata-file package/build-metadata.json
node scripts/workflow/write-sha256sums.mjs --metadata-file package/build-metadata.json
```

## 应用图标

- 使用经确认的蓝底白色几何 M 标识，字母内保留两处通信线路节点。
- `src-tauri/icons/icon.png` 保存由内置 ImageGen 制作的透明背景高分辨率母版；仅去除预览图外围背景，保留标识设计。
- `src-tauri/icons/icon.ico` 供 Windows 可执行文件、窗口和安装包使用；`public/favicon.png` 是同一母版生成的 64×64 浏览器图标。
- 更新母版后，用 `npx tauri icon src-tauri/icons/icon.png --output <仓库外临时目录>` 生成图标，将其中的 `icon.ico` 和 `64x64.png` 分别复制到上述位置。其他平台的生成物无需纳入仓库。
- ICO 保留 16、24、32、48、64、256 像素图层，目录项按尺寸降序排列，把 256×256 图层放首位；当前 Tauri 从首个图层读取窗口默认图标，重新生成后需同步检查目录顺序。
- `src-tauri/build.rs` 必须通过 `cargo:rerun-if-changed` 追踪 ICO 和 PNG。当前锁定的 `tauri-build` 不自动追踪 Windows ICO；如果仅替换图标资源，增量构建或 CI 恢复的 `target` 缓存可能继续使用旧的 EXE 图标资源。
- 验收时检查 PNG 透明通道、ICO 多尺寸图层以及 `npm run build` 输出的 favicon；还需检查构建产物 EXE 内嵌图标，不能仅以安装包或浏览器 favicon 已更新作为通过依据。重新打包、安装并完全退出旧进程后，确认标题栏、任务栏和桌面快捷方式均显示新标识。
- 图标维护仅涉及静态资源、favicon 引用和构建依赖追踪，不涉及业务运行逻辑或运行日志。

## 部署

- 方式一：
  - 解压交付 zip
  - 运行 `install.ps1`
- 方式二：
  - 直接运行交付目录中的安装包


## 日志查看

```powershell
.\logs.ps1
```

- 当前仓库已经补齐 workflow / packaging 侧日志与 diagnostics。
- 上位机优先在安装目录附近维护运行数据：
  - `data\settings.json`：非敏感界面配置；MQTT 密码写入 Windows 凭据管理器。
  - `logs\mskdsp-upper.log`：活动运行日志。
  - `cache\lower-update\`：下位机更新包缓存。
- 安装目录不可写时，上述目录统一回退到 `%LOCALAPPDATA%\com.mskdsp.upper\`。
- 活动日志达到 10 MiB 后自动轮转，超过 60 天的历史日志会在启动时清理。
- `logs.ps1` 会优先探测以下运行时日志目录：
  - 安装目录下 `logs`
  - `%LOCALAPPDATA%\com.mskdsp.upper\logs`

## 回滚 / 替换旧包

1. 先执行 `stop.ps1`
2. 备份旧版交付包与 `SHA256SUMS`
3. 使用新版本 `install.ps1` 或 `upgrade.ps1`
4. 若回退，重新运行旧版本交付包中的 `install.ps1`

## 约束

- 所有最终可交付文件都必须先进入 `package/staging`，再进入 `package/out`。
- 所有发布渠道都必须带 checksum 文件。
- symbols 包与主包需要同名基底，便于问题追踪。
- stable 包由手动推送 `v*` tag 触发 `release.yml` 构建发布（不再有 beta 自动晋升）。
