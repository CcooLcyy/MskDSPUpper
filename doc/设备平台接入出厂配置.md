# 设备平台接入出厂配置

在模块操作页，先通过 ModuleManager 地址连接现场下位机，再使用“设备平台接入配置”卡片。平台地址固定为 `60.208.15.90:50000`，不提供修改入口。该卡片仅在桌面上位机的在线直连模式可操作，平台远程模式不提供配置入口，Rust 命令也拒绝远程模式。

可以启用或禁用平台接入，填写平台分配的设备 ID、新设备令牌，以及 SSH 开关和下位机本机端口。读取只显示“令牌已配置”，不会返回已有令牌。新令牌留空保留原值；勾选“显式清除”须先关闭接入，且不能同时提交新令牌。更换已有令牌的设备 ID 时，必须同时提供新令牌或关闭后清除旧令牌。

“保存并立即应用”通过现有 ModuleManage 服务调用 `SetPlatformAccessConfig`。下位机校验修订后持久保存并热应用，无需重建容器；断电、重启和软件升级后保留配置并自行接入平台。保存成功与设备已上线分别显示；连接失败会显示脱敏原因，下位机后台自动重试。保存成功后清空新令牌输入，令牌不进入上位机工作区、应用设置或日志。

配置修订冲突不会自动重试覆盖，须点击“重新读取配置”后再保存。旧下位机未实现接口时明确提示升级；连接、持久化和超时分别反馈。连接建立和 RPC 共用 10 秒总期限，保存超时后需重新读取确认实际结果。请求绑定读取时的现场地址和连接代次，切换设备后旧响应不能回写，旧保存请求不能发送给新设备。后台状态刷新只更新状态，不覆盖未保存的令牌或端口草稿。

协议来源为设备 protobuf 子模块的 `ModuleManager.proto`，固定提交 `175c7efbce2fb95fc3a5128c1e59871ac75f3d87`。本次不修改 ConfigPusher 的业务配置来源。

本地验证使用随机 localhost 管理器服务：覆盖脱敏读取、空令牌保留、写入不回传秘密、64 位修订精度、旧版本、冲突不重试、远程模式拒绝、过期请求及地址切换隔离、无响应 TCP 对端的总超时。前端行为测试覆盖身份及令牌校验、显式清除、成功清空输入、切设备忽略旧回调、运行状态刷新不覆盖草稿。未向真实下位机或公网平台发送配置，也未启停已运行上位机；断电、升级及实际设备上线结果需与下位机验证证据分别确认。
