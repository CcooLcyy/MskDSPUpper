# 协议页源端实时值查询方案

## 目标

IEC104、ModbusRTU 和 DLT645 协议页面直接读取 DataCenter 保存的源端最新值，不再依赖 `MskDSPUpper/__protocol_shadow__` 影子连接、影子点位和影子路由。

## 数据流程

协议模块采集点值后继续调用既有的 `DataCenter.Publish` 或 `BatchPublish`。DataCenter 在发布时更新进程内源端缓存，并保留原有路由转发逻辑。上位机协议页面按源连接 ID 和页面点位 tag 周期调用 `GetSourceLatest`，将返回值合并到点表中显示值、时间戳和质量。

## 接口语义

- `GetSourceLatest(conn_id, tags)` 查询指定源连接的最新值；`tags` 为空表示查询该连接缓存中的全部点。
- 返回的 `SourcePointUpdate` 使用 `conn_id/tag` 标识源点，不包含目的连接字段。
- `sequence` 仅在 DataCenter 当前进程内单调递增，用于诊断和消费方判断更新顺序；进程重启后重新计数。
- 源端缓存不落盘，连接删除时同步清理；协议模块重启后由下一次 `Publish` 恢复页面值。

## 上位机实现

Tauri DataCenter 客户端、命令和 TypeScript 适配器提供 `dcGetSourceLatest`。公共 Hook `useProtocolRealtime` 首次进入页面立即查询，之后以 500 ms 间隔轮询；请求异常只影响当前页面的错误状态，不会清空既有值。页面切换连接或点位时清空旧连接数据，避免跨连接串值。

协议页不创建影子连接、不写入影子路由，也不订阅影子流。历史版本已经落盘的影子连接和路由需要在 DataCenter 状态迁移时清理，不能作为实时值来源继续使用。

## 边界条件

- 协议模块未调用 `Publish` 的点不会出现在源端缓存中，页面显示占位符。
- 死区过滤导致未发布的值不会更新缓存，这是现有协议模块发布语义，不在上位机侧补发。
- DataCenter 返回连接不存在或网络错误时，页面保留上一次成功值并显示错误状态。
