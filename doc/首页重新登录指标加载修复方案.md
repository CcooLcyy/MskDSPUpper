# 首页重新登录指标加载修复方案

## 问题与范围

退出账号会清空模块地址缓存。重新登录后，总览的运行模块刷新、设备指标读取与吞吐量读取分别执行，指标可能在地址就绪前请求 DataCenter。吞吐量首次失败后不再轮询，造成上方已同步、下方仍报地址未知。

本次仅修改总览页及其轮询辅助逻辑，不改变登录、下位机接口、模块配置或已有更新流程。

## 加载与异常处理

- 首页初始化、手动刷新、更新后的连接恢复均先暂停旧指标轮询，设置 Manager 地址并刷新运行模块信息。
- 本轮配置摘要加载返回且运行模块地址刷新成功后，加载 CPU/内存与吞吐量；其他配置分区部分失败不阻止指标加载。
- 地址刷新失败时不发出指标请求，保留现有失败提示，由用户刷新重试地址发现。
- CPU/内存请求结束约 5 秒后读取下一次，吞吐量请求结束约 1 秒后读取下一次；首次或后续指标读取失败仍继续重试，不并发堆积请求。
- 连续指标读取失败只在首次记录中文日志，吞吐量同时弹一次提示；恢复成功后允许记录和提示下一次故障。
- 每次刷新使用独立代次。旧刷新、旧指标的迟到结果不能覆盖新数据、关闭新刷新的加载状态或弹出旧错误提示；页面卸载后停止调度。
- 日志记录地址就绪、地址刷新失败、轮询失败与恢复；不在每次成功采样时刷屏。

## 验收

1. 缓存为空或地址刷新未完成时，CPU/内存与吞吐量请求均不执行；成功后才开始读取。
2. 指标首次失败后，下一采样周期成功即可恢复，不需要重新进入页面。
3. 手动刷新同步重启两类指标，地址发现失败不会误启动采样。
4. 新一代刷新或页面卸载后，旧请求成功、失败及定时器都不能再更新界面。
5. 慢请求不产生重叠轮询；部分配置失败仍可读取指标。

通过 Node 行为测试验证重试、取消、代次及串行调度，保留并扩展首页接线与地址加载顺序检查，再执行相关测试、TypeScript 构建与本次文件的 ESLint 检查。真实桌面退出再登录的联调结果单独确认。
