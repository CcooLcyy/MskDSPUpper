# IEC104 大点表交互性能优化

## 问题与范围

配置约 800 点后，滚动、勾选、编辑出现卡顿。源码确认点表全量挂载，配置视图仍执行 500 ms 全点实时查询；实时更新和表单输入会牵动整张表重新渲染。

本次只调整上位机 IEC104 页面，不变更下位机、点表保存接口及链路启停流程。

## 方案

- 独立、缓存点表组件，使用随容器高度调整的虚拟滚动，仅挂载可见区域及预加载行。
- 只在 IEC104 配置页的运行视图查询实时值，切回配置、SOE 或日志时停止查询。
- 无实时查询时返回稳定的空数据引用，避免编辑输入导致配置列缓存失效。
- 点表接收稳定的列、选择回调和空状态；保留按 Tag 识别行、跨筛选保留选择、排序、编辑和批量操作。
- 为操作列建立点位索引，避免每次绘制逐行查找原数组。

## 验收

- 800、2000 点时 DOM 中挂载行数随视口变化，不随总点数等比例增加。
- 滚动到底部仍能查看并编辑最后一点，筛选与多选不丢失点位身份。
- 编辑输入与连接状态定时刷新不触发无关点表重绘。
- 配置视图不轮询实时值；运行视图仍按原查询方向刷新，切回后停止。
- 通过相关工作流测试、TypeScript 构建、lint 及差异检查；浏览器验证使用模拟数据，与真机性能结论区分。

## 本地验证结果

- 工作流测试 433 项、离线测试 74 项全部通过；生产构建与严格 lint 通过。
- 真实 React SSR + 当前安装的 Ant Design 对照：旧表格分别输出 800、2000 行，新虚拟表在测试视口均输出 6 行。这是输出规模验证，不代表浏览器帧率。
- 浏览器模拟适配器配置 800 点：已验证滚动到底部、末行编辑保存、筛选后保留首末两点选择、运行视图实时显示及切回配置视图。
- 浏览器底部视口实测挂载 14 行；拖动面板后容器高度由 532 降为 455，虚拟滚动区由 493 降为 416，挂载行数为 12。
- 本轮未连接设备，未测量真机负载或当前安装版 WebView 的帧率。
