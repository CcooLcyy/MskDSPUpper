# 内置纵密配套证书

本目录包含用户授权内嵌的 NSS3000 V1.1.E.4242 配套客户端身份及信任证书。

- `*.p12`：在内存读取原材料后，以新的随机口令重打包的加密 PKCS12；不包含明文私钥文件。
- `*.unlock`：对应的随机解锁种子。程序由种子派生重打包口令；原软件的原始证书口令不随程序保存。
- `*.der`：从配套 JKS 验证完整性后提取的公共信任证书。
- `manifest.json`：来源、指纹、公有有效期及公私钥一致性检查结果；不包含纵密管理账号或 DSP SSH 凭据。

以上身份及解锁材料随程序分发，能够从程序中提取，不能声称它们在安装包中不可获取。
它们仅完成正常的配套 TLS 客户端身份连接，不能替代纵密账号认证。

旧组证书已于 2019-09-17 到期，保留为原材料来源，运行时跳过，不使用它发起 TLS。
当前默认选用有效期为 2022-03-28 至 2122-03-04 的新组。运行时同时核对客户端与信任证书有效期，
每次登录再次检查缓存候选；服务器证书链、有效期和名称校验保持启用，默认名称为 `11.22.33.44`。
真实服务端名称、TLS 兼容性及正常登录成功码仍需设备联调。

资源已经实际核验两组均可解锁且公私钥对应，公有元数据与解析结果一致。
可执行 `python scripts/prepare-vertical-security-certificates.py --verify-output` 进行仅读核验，
不改写随机资源、不连接设备、不打印私钥或原口令。重新准备需要 Python `cryptography` 与原分析目录，
仅在明确需要更新资源时使用 `--source <原分析目录>`；不要将用户账号密码传入该脚本。
