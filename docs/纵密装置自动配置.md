# 纵密装置自动配置的数据来源

## 目标与前置条件

安全操作员工作台的“自动配置”从当前 DSP 已部署的正式脚本读取业务地址，不能使用上位机旧业务地址缓存放行。DSP 脚本部署成功、正在等待 PPP IPv4 时，即可生成纵密四页配置；PPP 路由和 NAT 是否全部应用不作为生成条件。

SSH 目标、账号和认证方式关联到“DSP 网络配置”页面当前连接。磁盘仅保存连接目标和认证方式；密码只在当前进程内存中复用，缺失时按该精确目标读取已有系统凭据。没有目标或认证资料时提示回该页面补齐，不使用上一台设备的凭据。

## 读取与上传

1. 点击现有“自动配置”按钮，通过普通 SSH 检查正式服务文件，并读取 `/usr/local/libexec/mskdsp-vertical-security`。
2. 静态解析生成脚本头部的设备标识及六个 IPv4 地址；不执行、source 或修改脚本，不读取等待 PPP 后才生成的配置文件，不需要 sudo。
3. 从当前纵密装置读取证书及四页配置，生成预览并显示 DSP SSH 目标。
4. 确认后再次读取设备脚本。目标、脚本 SHA256 或操作员会话变化时停止，要求重新生成预览。
5. 按网络、路由、隧道、策略顺序上传，每页回读一致后继续。全部成功后退出安全操作员，认证管理员并发送纵密装置重启命令；任一步失败均不继续或自动重试。

已有旧版脚本只要符合当前生成器格式即可读取，无需为建立上位机完成记录而重新部署。脚本缺失、不可读、格式不支持、地址缺失或重复时不生成配置。读取正式脚本依赖设备上的 `od` 命令；不满足时明确报读取失败。

## DSP 页面执行状态

页面独立区分“脚本已部署，正在查询执行状态”“脚本已部署，等待 PPP 地址”“正在配置 DSP 业务网络”“全部执行完成”“执行失败”“当前执行状态未确认”。不能因服务为 active 就把等待 PPP 标为完成，也不能以旧步骤快照覆盖查询失败状态。

设备端现有等待、取得 PPP 地址后的路由和 NAT 应用、重拨监控逻辑保持原样。上位机切页停止该页状态查询，后台服务继续运行；本次不增加常驻监控。

## 验收范围

- 无 PPP IPv4 但正式脚本已部署时，四页预览可生成。
- 旧本地业务地址记录、缺少 SSH 认证、设备读取失败均不能放行。
- 换目标不复用旧密码；确认前脚本或目标变化时不上传；上传期间目标变化时停止后续页及重启。
- 磁盘记录不含 SSH 或 sudo 密码，读取命令不执行脚本，不写设备。
- 等待、执行中、查询失败、重拨残留旧成功步骤与全部完成有独立状态用例。

自动化验证统一交对应提交的 CI；设备端实际 PPP 恢复、纵密通信及重启效果另行联调核实。
