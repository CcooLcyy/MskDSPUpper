# 下位机更新期间的隧道断线与原任务恢复

## 目标与范围

2026-10-29 现场更新在替换业务容器时关闭平台 SSH 隧道。宿主机独立任务已成功，上位机却在发送 sudo 输入期间等待至 30 秒总时限，只能展示结果未知。此次仅调整上位机通信与原任务观测，不改下位机、平台服务、安装器或设备配置，不执行真机更新。

## 行为约定

- 查询所用平台隧道关闭后，及时结束本次通信，不依赖 30 秒总时限。覆盖 SSH 建连、命令/输入发送及响应读取；不得让某个旧隧道的断开影响新查询或其他会话。
- 已收到完整退出码的响应优先于同时发生的隧道关闭；完整非零退出码（例如 sudo 拒绝）仍作为原命令错误处理。没有退出码的空响应或部分响应不能当作完整成功，也不能仅凭随后断线把已确认的协议/认证错误改为可重试。
- 明确的可恢复隧道中断使用内部错误标记 `LOWER_UPDATE_TUNNEL_INTERRUPTED:`；平台设备暂时离线或隧道暂不可用可用同一标记。鉴权失败、权限撤销、主机指纹变化、平台账号/目标变化、无效协议及业务任务错误不得标记为可恢复中断。
- 标记只用于内部分类，界面显示中文说明。已保存原任务身份后，自动观测遇到明确的可恢复中断显示“等待连接恢复，安装结果待确认”，保留日志、原任务及恢复材料，不显示安装失败，不推断安装成功。
- 自动观测仅重新查询原任务，固定原平台、设备、任务编号和期望镜像；不重传安装包、不再次提交安装、不新建任务、不自动切换直连地址。重新查询应使用新连接，不能复用已关闭的 SSH 会话。
- 自动观测维持原有 180 秒总预算（包含请求和等待），可恢复中断最多连续重试 12 次，每次等待不超过 3 秒且受剩余预算限制。预算或次数耗尽保留结果未知，提供手动恢复入口。成功获取执行中状态后重置连续中断次数；终态仍验证原任务编号与镜像后再收尾。
- 人工“恢复查询原任务”保持单次查询语义，直连恢复及其主机指纹校验不变。认证、指纹、权限、协议错误应立即停止自动观测并说明原因；不得因自动重试掩盖这些问题。
- “停止等待”立即结束本轮本地观测；停止后的迟到成功/失败不得消费恢复记录或改变下一轮状态。终态落盘及清除记录沿用已有事务边界。凭据仅保留在内存，日志与公开快照必须去密。

## 验收

先新增失败测试，再实现：隧道关闭时挂起的输入/EOF等待及时结束；认证/权限/协议错误不重试；首次中断后连接恢复并返回原任务成功时自动收尾且仅提交一次；反复断线受次数与总预算限制；等待期间停止及迟到结果无副作用；原有手工单查、直连、回退和终态核验用例继续通过。所有测试使用本地隔离服务或替身，不以此替代真机更新验收。

## 实现与验证记录

更新命令使用独立的本地 socket、平台 SSH 隧道及会话关闭信号，释放时只取消本次会话；普通上传与其他服务 adapter 保持原有路径。完整响应与关闭同时就绪时优先消费完整响应，必要时以 100 毫秒有界排空等待已到达的结果或永久拒绝原因。SSH 错误按类型区分传输和协议失败，并通过后台断线回调保留响应阶段的协议原因；等待关闭原因后再次检查永久拒绝，避免竞态覆盖。

红绿证据：前端首批 6 个新用例在旧实现全部失败，修复后通过，另补永久错误不重试用例；Rust 新隧道用例先因缺少受监测连接 API 失败，再由真实本地 tonic/socket 替身验证中断。独立审查补充的“等待期间才确认协议拒绝”确定性用例先复现返回临时中断标记，再通过返回前二次检查修复。最终远程部署定向 49/49、完整 workflow 616/616、Rust lib 385/385 通过，前端构建、严格 lint 与 `git diff --check` 通过。构建仅有既有 chunk 大小提示。

本轮未修改下位机或平台服务，未连接真机执行更新、未安装或发布上位机客户端。正在运行的旧客户端不会自动获得此行为，需使用包含本次改动的上位机版本后生效。
