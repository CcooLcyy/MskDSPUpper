# Cloudflare R2 更新包发布

GitHub Actions 在 Windows runner 上完成构建后，使用 AWS CLI 的 S3 兼容接口将上位机更新资产上传到 Cloudflare R2。R2 对象按以下路径组织：

```text
<R2_PREFIX>/<channel>/<platform>/<资产文件>
<R2_PREFIX>/<channel>/latest.json
```

资产（安装包、签名文件、SHA256SUMS 等）全部上传成功并完成验证后，`latest.json` 才最后上传。发布脚本随后只清理该 channel/platform 前缀下不再被清单引用的旧对象，不会删除其他渠道或平台的文件。

## GitHub 配置

Actions Variables：

- `R2_BUCKET`：R2 存储桶名称，默认 `mskdsp-update`。
- `R2_PREFIX`：对象前缀，默认 `mskdsp-upper`。
- `R2_PUBLIC_BASE_URL`：R2 公共访问根地址（不包含 `R2_PREFIX`），例如 `https://pub-xxxx.r2.dev`。绑定自定义域名后可替换为正式地址。

Actions Secrets：

- `R2_ACCOUNT_ID`：Cloudflare 账户 ID，用于构造 S3 endpoint。
- `R2_ACCESS_KEY_ID`：仅限目标 Bucket 的 R2 API Token Access Key。
- `R2_SECRET_ACCESS_KEY`：对应的 Secret Access Key。

发布步骤通过环境变量 `AWS_ACCESS_KEY_ID` 和 `AWS_SECRET_ACCESS_KEY` 将密钥传递给 AWS CLI；密钥不会写入命令参数或日志，也不应放入上位机程序。

## 发布脚本

`scripts/workflow/Publish-R2StaticUpdater.ps1` 参数：

- `-PackageOutputDir`：包含 `latest.json` 和更新资产的目录。
- `-ChannelPath`：`ci`、`beta`、`nightly` 或 `stable`。
- `-Platform`：默认使用 `PLATFORM_ID`，当前为 `windows-x64`。

脚本要求 runner 已安装 AWS CLI，并会通过公共 URL 读取 `latest.json`、HEAD 检查首个资产。脚本只操作传入的 channel/platform 前缀；发布失败时不会主动删除旧对象。

## 首次启用

1. 在 R2 创建 Standard Bucket，并创建仅对该 Bucket 有读写权限的 API Token。
2. 在仓库 Variables/Secrets 中配置上述变量和密钥。
3. 先手动运行 `Sync Static Updater Source` 工作流验证开发 `r2.dev` 地址，确认上位机可以读取清单、下载并校验安装包。
4. 稳定后再绑定自定义域名，并更新 `R2_PUBLIC_BASE_URL`。

R2 公共开发 URL 适合联调；生产环境建议使用自定义域名，并为 `latest.json` 保持短缓存或 `no-store`，带版本号的资产使用长期缓存。
