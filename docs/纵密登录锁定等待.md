# 纵密登录锁定等待

纵密登录应答返回锁定剩余秒数时，上位机显示倒计时，并在等待期间阻止该账号再次发送认证请求。倒计时结束只恢复手动尝试，不代表装置已确认解锁，也不自动登录。

## 范围与约束

- 时长仅采用装置应答，不根据本地错误次数附加锁定。普通凭据错误不创建计时。
- 记录按访问模式、远程 DSP 标识和原始用户名区分；同一用户名跨角色共用记录。直连目前只有固定纵密管理目标。现有协议资料不能证明整机或跨账号锁定，不扩展到其他账号。
- Rust 后端保存单调时钟截止时间；入口及发送认证之前拦截，防止并发请求或直接 IPC 调用绕过界面。同账号同时只允许一个认证过程。
- 前端从后端读取有效锁定，按截止时间计算剩余秒数并向上取整。页面切换、WebView 刷新、切换证书或角色不清除后端记录；上位机进程退出不持久化，重新启动后仍由装置执行真实锁定。
- 再次收到有效锁定时长时，以新应答更新截止时间。零秒不额外等待；时长缺失或损坏时保留装置锁定错误，不虚构倒计时或无限期本地锁定。
- 不保存密码、摘要或证书秘密；日志不记录用户名和认证数据。

## 验收与回归

1. 返回正数秒数后显示动态剩余时间，按钮及回车均不能提交；绕过界面调用后端也不会建立认证连接或发送凭据。
2. 切页返回、刷新页面、修改角色后同账号仍受限制；其他账号和其他目标不会继承该锁定。
3. 到期后恢复手动登录，期间没有自动认证；前台恢复、计时器延迟时按真实经过时间更新，不逐次减一积累误差。
4. 普通凭据拒绝、未知结果、零秒和无效秒数字段不产生臆造的等待时间；新锁定应答更新等待时间。
5. 单调时钟边界、并发认证、记录恢复和倒计时展示由 Rust/工作流回归覆盖，浏览器夹具覆盖实际 React 交互。

构建、静态检查和自动化测试仅通过本次提交的现有 CI 执行；浏览器夹具若未被 CI 覆盖，单独报告未执行，不以本地测试补充。
