# Stable 客户端更新通道限制

Stable 上位机只允许下载和安装属于 Stable 发布通道的上位机、下位机软件包。只有 CI 上位机可使用现行 CI/Stable 通道；历史 Beta 版本按 Stable 限制处理，不再查询、下载或安装 Beta 通道包。

客户端通道由正在运行的上位机版本确定：仅包含 `-ci.` 的版本识别为 CI，其余版本（包括历史 `-beta.`）均按 Stable 处理；版本尚未读取成功时不开始自动下载。目标包通道以平台发布归属为准，已经晋升 Stable 的不可变包可保留原构建版本字符串。

界面只展示客户端允许的下位机通道，自动检查与自动下载采用相同规则。Stable 及历史 Beta 客户端默认选择 Stable；x64 当前只提供 CI，因此这些客户端不提供 x64 更新。原生后端独立校验检查、下载、缓存、上传和安装入口，拒绝使用既有 Beta/CI 缓存绕过界面限制。

本地下位机安装包目前没有可信发布通道信息，统一标记为 CI，因此 Stable 客户端禁用本地导入。仅 CI 客户端仍可导入符合现行规则的包；历史 Beta 客户端与 Stable 客户端同样禁用本地导入。Stable 安装必须关联后端验证过的 Stable 缓存身份，并核对待安装文件，不能只信任前端传入的通道或镜像名称。

验收覆盖 Stable、历史 Beta、CI 客户端的通道矩阵（历史 Beta 仅允许 ARM64 Stable、x64 无可选通道，后台不请求 CI/Beta）、启动读取版本前的检查行为、Stable 缓存及本地导入限制、直接调用后端下载/上传/安装时的拒绝行为，以及已有架构和更新流程回归。测试使用本地夹具，不连接或更新真实设备。
