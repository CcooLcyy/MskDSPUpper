# 平台 gRPC 安装包接入

## 目标与边界

桌面上位机通过平台 gRPC 查询并下载 `mskdsp-upper` 与 `mskdsp-lower` 安装包，不读取 HTTP `latest.json`，不回退 R2。平台既有网页下载、HTTP 清单和旧客户端兼容入口保留；下位机本地导入、已校验缓存、SSH 上传及安装流程保留。浏览器开发模式不具备原生 gRPC 下载能力，明确提示使用桌面客户端，不偷偷访问旧 HTTP 更新源。

本轮不自动运行安装器、不更新真实下位机，也不改动已有 GitHub Beta/Stable 发布工作流。现有未提交的 GitLab CI 文件属于先前工作，独立保留和核对。

## 协议与下载

平台 `SoftwareCatalogService` 提供 `ListPackages`、`GetPackage`，新增 `DownloadPackage` 服务端流。请求指定不可变包 ID 和已接收偏移；响应逐块携带偏移、数据、总长度、SHA256 和结束标志。单块最多 256 KiB；文件末尾允许空结束块，超出末尾返回 `OUT_OF_RANGE`。未发布包和平台自身的私有候选不可读取；公开历史包沿用现有访问规则。

上下位机共享桌面 Rust 下载实现：按产品、通道、架构选择包；开始或恢复下载时重查包 ID 和完整身份；验证连续偏移、长度、摘要和明确流结束；校验成功才将临时文件转为可安装缓存。中断保留身份绑定的临时文件以便续传，损坏或身份变化的文件不能作为成功缓存。普通日志记录阶段、包 ID、字节进度和错误，不记录凭据。

平台地址通过持久设置 `softwarePlatformGrpcEndpoint` 配置，默认 `http://192.168.10.198:50000`。使用 HTTPS 时执行正常证书验证；明文只允许回环和内网 IP，地址中不允许凭据、路径、查询串或片段。修改地址在下一次检查时生效。

## 上位机自身更新

保留现有每 30 秒检查、自动下载、用户明确操作后安装的行为。前端改用 Tauri command，不调用插件的 HTTP `check`。下载进度事件按 task ID 隔离，所有监听器在成功或失败后释放。新包未通过大小、SHA256 和原 Tauri 公钥签名校验时不替换已经可安装的旧包；安装前再次验证文件。相同版本但包 ID 或摘要变化也不能误复用旧下载。

现有 `tauri-plugin-updater 2.10.1` 的公开 API 不能直接从本地目录元数据构造更新，且 `install(bytes)` 本身不验签。因此保留其许可证和来源，使用最小本地扩展构造离线更新、复用原签名验证与 NSIS 安装行为；不增加 HTTP 伪清单，不跳过签名，不在测试中执行安装器。

## 下位机更新

目录结果转换为现有安装流程使用的清单 DTO，并补充 `platform_package_id`。网络清单不包含 HTTP 资源 URL；网络下载必须重新向平台核对该包 ID 的产品、通道、架构、大小和 SHA256。ARM64 保留 ci/beta/stable，x64 保留当前仅 CI 规则。旧缓存和本地导入清单仍可离线使用，不能据其旧 URL 发起新下载。

## 验收

- 平台真实随机端口 gRPC 测试覆盖上下位机文件、多块、断点续传、结束偏移、越界、候选访问及损坏。
- 桌面下载测试覆盖块身份与偏移错误、截断、摘要错误、续传、缓存身份、签名和旧包保留；不真实启动安装器。
- 前端测试运行实际适配器，验证 command 参数、进度关联、失败清理监听及平台地址校验；保留现有更新调度、架构和安装选择行为。
- 运行前端 workflow/offline、严格 lint 与生产构建，以及相关 Rust 测试。部署和真实下载验证另记确切版本、范围与结果，不把源代码测试等同设备升级验证。

## 集成与上线顺序

先提交独立协议并固定平台子模块、上位机协议快照的来源，再提交相关服务与客户端。上线先部署并确认平台 `DownloadPackage` 可用，再发布启用本轮功能的上位机包；旧平台缺少该 RPC 时客户端会明确失败，不回退 HTTP。平台保留旧 HTTP 入口，使原客户端在过渡期可继续工作。
